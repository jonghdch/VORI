# 1학기 기획 vs 현재 구현 대조

> 2026-03-29 4차 팀 회의록에서 확정한 사항을 2026-09-09 시점의 코드·DB 와 하나씩 맞춰본 기록.
> 최종보고서의 "설계와 달라진 부분" 절에 그대로 쓸 수 있게 정리했다.
> 구현 여부는 추정이 아니라 저장소 코드·DB·실행 중인 앱에서 확인했다.

---

## 요약 — 한 문장

**회의록의 가장 큰 결정("가계부는 서브, 동물 육성 게임이 메인")이 뒤집혔다.** 구현은 가계부를 만들었고, 9월 시장 조사도 가계부 쪽이 맞다고 가리킨다. 이건 표류가 아니라 **현실이 기획을 교정한 것**이므로, 기획서를 현실에 맞추면 된다.

---

## 1. 뒤집힌 전제 — 이게 가장 중요하다

### 회의록의 판단 (3/29)

> "기존 가계부 앱들(토스, 뱅크샐러드 등)과 차별화 포인트가 없다" → 전원 동의
> **최종 결정: 가계부는 서브 기능, 동물 육성 게임이 메인 정체성**

### 9월에 확인한 사실

**펫 육성이 가계부보다 더 레드오션이었다.**

| 서비스 | 캐릭터 육성 |
|---|---|
| 토스 | 고양이 키우기 |
| 카카오뱅크 | 한달적금 춘식이 키우기 |
| 케이뱅크 | 돈나무 키우기 |
| 뱅크샐러드 | 샐러드게임 (5일 예산 절약, 앱머니 환급) |
| 지갑펫 | 소비 기록 + 등급별 펫 도감 |

**3월에 "차별화가 없다"며 서브로 내린 그 기능이, 실제로는 유일한 차별점이었다.**
z-score 로 개인 기준선을 만들어 이례를 잡고, AI 가 사유를 물어 판정을 조정하는 것 — 이걸 하는 경쟁자는 확인되지 않았다. 자세한 근거는 [`market-research.md`](market-research.md).

### 구현이 이미 그렇게 말하고 있다

말이 아니라 **코드가 증거다.** 칭호 13개를 보면 프로젝트가 어디로 갔는지 드러난다.

| | 회의록의 업적 예시 | 실제 구현된 칭호 |
|---|---|---|
| 기준 | **펫 성장** | **가계부 행동** |
| 예 | 매력 스탯 200 달성 · 단일 스탯 유년기 졸업 · 성체 최초 달성 | 누적 절약 10만원 · 지출 10건 기록 · 절약 목표 달성 · 영수증 10회 인식 |

13개 중 **펫 관련은 3개**(첫 분양·펫 컬렉터·행운아)뿐이고, 나머지 10개가 가계부 행동 기반이다.

그리고 회의록에 **없던** 기능이 대거 추가됐다 — 영수증 AI 인식, 월 예산, 절약 목표, 일일 리포트. 전부 가계부 쪽이다.

### 평가 배점도 같은 방향을 가리킨다

2학기 배점은 **작품 평가 50%(기술난이도 20 + 완성도 30)** 다. 기술적 성과는 EMA·z-score 개인화 탐지와 Gemini 이미지 인식에 있고, 둘 다 가계부 쪽이다. **"동물 육성 게임"으로 소개하면 그 성과가 묻힌다.**

### 그래서 제안

> **포지셔닝을 "지출한 이유를 묻는 가계부"로 되돌린다.**
> 펫·가구·칭호는 **그 판정을 계속 쓰게 만드는 장치**로 설명한다. 상품이 아니라 장치다.

## 2. 회의록과 구현이 어긋난 것

전부 코드에서 확인했다.

| # | 회의록 (3/29) | 실제 구현 (9/9) | 판단 |
|---|---|---|---|
| 1 | 스탯 **최대 100점 · 총 400점 만점** | **상한 없음.** 시연 계정 펫이 스탯 730 | 🔴 고칠 것 |
| 2 | 유년기 <200 / 청소년기 ≥400 / **성체 ≥600** | JUVENILE 200 / **ADULT 300** | 🟡 문서 갱신 |
| 3 | 충동 소비 = **−스탯 (최대 −10)** | **감점 없음** — `max(saved_amount, 0)` | 🟡 결정 필요 |
| 4 | 외형 = **유년기 최고 스탯으로 결정** | **가챠로 뽑은 종족에 고정** | 🟡 문서 갱신 |
| 5 | AI 검사 **버튼, 저녁 8~12시만 활성** | **버튼 없음.** 지출 등록 시 자동 발행 | 🔴 화면 문구와 불일치 |
| 6 | 럭셔리 침대 = 분양가 **15%** | 가구 개별 **1.00~4.00%** + 세트 8~15% | 🟢 현재가 나음 |
| 7 | 소비 판정 **3단계** (합당/어쩔수없는/충동) | **6종** ReasonCategory | 🟢 현재가 나음 |
| 8 | 칭호 장착 → **키우기 배경 테마 변경** | 테마 = **가구 세트 보너스** | 🟡 다른 것이 됨 |

### 🔴 1번 — 성장 곡선이 완전히 깨졌다

회의록은 **"1주일 캐릭터 키우기 체험"** 을 상정했고, *"200점 구간을 길게 잡은 이유"* 까지 적어 두었다. 외형이 그 구간에서 결정되니 천천히 쌓여야 한다는 의도였다.

그런데 지금 공식은 `stat_delta = 절약액 / 1000` 이고 **상한이 없다.**

```
시연 계정 실측 — 지출 9건으로 스탯 730
지출 2건만으로도 성체(300) 도달 가능
```

**기획이 상정한 1주일이 2건으로 줄었다.** 400점 만점이라는 전제도 무너졌다(730 > 400).

의도한 페이싱을 되살리려면 스탯당 절약액을 올리거나(1,000원 → 5,000원) 일일 상한을 두어야 한다. 다만 **지금 바꾸면 시연 각본과 `demo_seed.py` 를 다시 맞춰야 한다.** 발표 전에 손댈 일은 아니고, 최종발표 전 과제로 두는 편이 낫다.

### 🔴 5번 — 화면이 거짓말을 하고 있다

홈 대시보드에 이렇게 떠 있다.

> **"매일 오후 8시에 보리가 소비 검사를 시작해요"**

실제로는 **저녁 8시 버튼이 없다.** 지출을 등록하면 그 자리에서 AI 질문이 발행되고, 일일 리포트 스케줄러는 `0 10 0 * * *` — **자정 10분**에 돈다.

회의록의 "8~12시 제한"은 주작 방지가 목적이었는데, 구현은 다른 방식(과거 날짜 수정 시 스탯 불변, EMA 기반 판정)으로 그 목적을 이미 달성한다. **기능을 되살릴 게 아니라 문구를 고쳐야 한다.**

### 🟡 3번 — 충동 감점, 결정이 필요하다

회의록은 충동 소비에 **−10 스탯**을 명시했다. 구현에는 감점이 없다.

> 참고로 이 차이가 최근 혼선을 만들었다. 인정 보상을 설계할 때 "충동이면 감점, 합리적이면 페널티 면제" 라는 제안이 나왔는데, **면제할 페널티가 애초에 없어서** 그 설계는 동작하지 않았다. 회의록의 기억과 구현의 현실이 어긋나 있었던 것이다.

현재는 `c858dc7`(인정 보상)로 **가산 방식**을 택했다 — 인정받으면 스탯 +10·코인 +100, 충동이면 0. 감점 없이도 차등이 생긴다.

**감점을 되살릴지는 팀 결정이다.** 되살리려면 `expenses.stat_delta` 가 `INT UNSIGNED` 라 스키마를 바꿔야 하고, 펫 단계가 내려가지 않는 문제(`evaluateStage` 는 상향 전용)도 함께 풀어야 한다. **권하지 않는다** — 혼내는 앱은 이탈을 부르고, 2026 트렌드도 "선별"이지 "처벌"이 아니다.

## 3. 회의록에서 살릴 것 — 그대로 맞았던 결정

| 결정 | 상태 |
|---|---|
| **4대 스탯 매핑** — 에너지(식비) / 매력(쇼핑·뷰티) / 지능(문화·여가) / 지구력(생활·고정비) | ✅ DB 에 **정확히 그대로** 구현됨 |
| **0점 시작 → 쌓는 성장 방식** (100점 감점 폐기) | ✅ 구현됨 |
| **수기 입력** (금융 API 포기) | ✅ 구현됨. 게다가 이게 강점이 됐다 — 자동 수집된 거래엔 "왜 썼는지" 물어볼 사람이 없다 |
| **단일 재화(게임 머니) 통합** | ✅ 재화 분리를 보류한 판단이 옳았다 |
| **평균 기반 판정** (인위적 절약 방지) | ✅ EMA + z-score 로 구현. 다은 언니가 제안한 그 로직 |
| **도트 스타일** | ✅ 상점·펫 모두 픽셀아트 |
| **최초 알 랜덤 · 희귀 알 구매** | ✅ 가챠 3등급(기본/고급/최고급)으로 구현 |

**특히 "평균 기반 로직"은 회의록에서 가장 잘한 판단이다.** 교통비 예시(0원 쓴 날이 평균을 낮춰 나중에 1,000원도 낭비가 됨)가 그대로 z-score 설계로 이어졌고, VORI 의 유일한 기술적 차별점이 됐다.

## 4. 뺄 것 — 21일 안에 못 하고, 안 해도 된다

회의록의 게임 기능 **7개가 전부 미구현**이다. 코드에서 관련 문자열이 하나도 나오지 않는다.

| 기능 | 판단 |
|---|---|
| 상점 단계별 해금 (분양 10회 → 2단계) | **빼기.** 테마 해금이 같은 역할을 이미 한다 |
| 소셜 — 닉네임/코드 검색 방문 | **빼기.** 각본에 없고 DB·화면 신규. 최종발표로 |
| 동물 염색약 · 이목구비 변경권 | **빼기.** 에셋이 없다 |
| 마이룸 모자·악세서리 | **빼기.** 가구로 충분하다 |
| 무지출 보너스 · 대중교통 인증 퀘스트 | **빼기.** 인증 수단이 없다 |
| 칭호 → 키우기 배경 테마 변경 | **다른 것이 됐다.** 테마는 가구 세트 보너스로 구현. 배경 변경은 마이룸에 별도로 있음 |
| 튜토리얼 (1주일 체험) | **줄여서 살리기** — 아래 참조 |

**빼는 게 손해가 아니다.** 반쯤 된 기능 일곱 개보다 완전히 도는 네 개가 발표에서 강하다.

## 5. 빈틈 — 회의록에도 있었고 지금도 필요한데 없는 것

### 온보딩 — 이게 가장 큰 빈틈이다

회의록의 튜토리얼 기획은 정교했다(닉네임·성별·나이·직업·총 자산·월 고정지출·최소 1개월 소비내역 수집 → 1주일 체험). **전혀 구현되지 않았다.**

그리고 이게 코드의 다른 제약과 정확히 맞물린다.

```
ExpenseService: 지출 5건 미만이면 z-score 계산을 건너뛰고 무조건 GREEN
```

**즉 신규 사용자는 첫 5건 동안 VORI 의 핵심 가치(판정)를 전혀 경험하지 못한다.**

시장 데이터로 보면 이건 치명적이다 — 앱 설치자 4명 중 3명이 하루 만에 떠나고, 금융 앱 Day 1 리텐션은 약 30% 다. **첫날 핵심 가치를 못 보여주면 그 30%도 못 잡는다.**

다만 회의록의 온보딩은 **너무 길다.** 온보딩이 길수록 이탈률이 오르고, 앱의 핵심 가치 하나만 짧게 전달하는 편이 효과적이라는 게 일반적인 권고다. 자산·직업·1개월 내역까지 묻는 건 가입 허들이 된다.

**제안** — 최종발표(11/4) 과제로 두되, 방향은 이렇게:

```
회의록안   닉네임·성별·나이·직업·총자산·월고정지출·1개월 소비내역  → 너무 김
줄인안     "평소 한 끼에 얼마 쓰세요?" 같은 질문 3개로 기준선을 미리 채운다
           → 첫 지출부터 판정이 나온다
```

기술적으로도 맞는 방향이다. `user_stat_stats` 의 `mean_ema`·`sample_count` 를 초기값으로 채우면 5건 제약이 사라진다.

### 모바일 전환 — 로드맵에 있는데 아무도 안 꺼냈다

회의록 로드맵의 마지막 줄이다.

> 1학기 — 웹 기반 개발 완성 → **2학기 — 모바일 앱으로 전환 검토**

지금 2학기이고 여전히 웹이다. **21일 안에 전환은 불가능하다.** 검토 결과를 최종보고서에 명시하는 편이 낫다 — "웹으로 유지하기로 결정, 근거는 ○○" 이라고 쓰면 계획을 지킨 것이 되고, 아무 말도 없으면 빠뜨린 것이 된다.

## 6. 규제 — 지금 문제는 아니지만 알고 있어야 할 것

VORI 에는 확률형 아이템(알 가챠)이 있다. 한국은 2024년 3월 22일부터 **확률형 아이템의 종류와 공급 확률 표시가 의무**이고, 게임물·홈페이지·광고물 각각에 표시해야 한다. 위반 시 손해배상에서 사업자가 고의·과실 없음을 입증해야 하고, 2026년에는 컴플리트 가챠 금지를 담은 개정안도 발의됐다.

**현재 VORI 는 문제가 없다.**
- 이 규제는 **유상**으로 얻는 확률형 아이템이 대상이다. VORI 코인은 절약으로만 얻고 현금 판매가 없다.
- 그리고 **이미 상점 화면에 확률을 표시하고 있다** (기본 알 S1/A5/B24/C70 등).

**단, 코인을 현금으로 파는 순간 적용 대상이 된다.** 수익 모델을 논의하게 되면 이 지점을 먼저 확인해야 한다.

최종보고서에는 이렇게 쓸 수 있다 — *"확률형 아이템 표시 의무(2024.3 시행)를 참고하여 무상 재화 기반으로 설계하고, 확률 정보를 상점 화면에 상시 노출함."*

| 3 | 성장 곡선 재조정 (스탯 730 문제) | **최종발표 전 과제로.** 지금 바꾸면 시연 각본을 다시 맞춰야 함 |
