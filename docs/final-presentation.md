## 1. 작품 소개 · 0:40

*(랜딩 첫 화면)*

> 안녕하세요, VORI 팀입니다. 저희가 만든 건 대학생·사회초년생을 위한 **지출한 이유를 묻는 가계부**입니다.
>
> 대부분의 가계부는 얼마 썼는지 보여 주고 끝납니다. VORI 는 하루 예산을 넘긴 날 평소와 다른 큰 지출이 있으면
> **왜 썼는지 묻고, 그 답을 판정에 반영합니다.** 그리고 아낀 만큼 펫이 자랍니다. 오늘은 앱을 직접 눌러 보여 드리겠습니다.

> 💡 경진대회 교수님들은 VORI 를 처음 본다 — 첫 두 문장으로 「누구를 위한 무엇」을 끝낸다.
> 「게임」이라고 소개하지 않는다. 펫은 「계속 쓰게 만드는 장치」로 설명한다(9월과 같음).

## 2. 문제 · 0:35

*(가계부 월간 표)*

> 가계부를 써 보신 분들은 대부분 중간에 그만두셨을 겁니다. **기록만 쌓이고 아무것도 안 바뀌기** 때문입니다.
> 자동 연동 앱은 입력은 편하지만, 자동으로 들어온 거래에는 왜 썼는지가 없습니다.
> 대학생 조사에서 절약 의지는 **81.6%** 인데 충동구매 경험은 **44.7%** 였습니다. 쓰는 순간을 돌아보게 해 주는 게 없어서 생기는 간극입니다.

## 3. VORI 의 답 · 0:25

> VORI 는 판정을 **규칙**이 합니다. 그 사람의 기준선으로 하루 예산을 계산해 오늘 쓴 돈과 비교합니다.
> **AI 는 판정하지 않고**, 큰 지출에 이유를 묻고 답을 분류하는 일만 합니다. 바로 보여 드리겠습니다.

> 📌 9월 발표 때는 「AI 가 판정한다」로 들릴 여지가 있었다. 지금은 **규칙이 판정, AI 는 묻고 분류**로 못 박는다(랜딩 문구도 #133 에서 같게 바꿨다).

## 6. 기술 · 0:50

*(최종 판정 화면을 다시 띄운다)*

> 방금 판정은 세 가지로 움직입니다.
> **첫째, 개인 기준선** — 가입 설문으로 기준선을 잡고 지수 이동 평균으로 갱신해, 이번 지출이 평소에서 얼마나 떨어졌는지 봅니다. 그래서 첫 지출부터 판정됩니다.
> **둘째, 하루 예산** — 오늘 쓸 수 있는 돈의 85% 이하면 여유, 100% 이하면 적정, 넘으면 초과입니다. 남긴 돈의 절반은 내일로 넘어갑니다.
> **셋째, AI 는 세 군데만** — 질문 문구, 글로 쓴 이유 분류, 영수증 인식. AI 가 안 돼도 칩과 기본 문구로 앱은 멈추지 않습니다.

> 📌 질문이 오면 쓸 숫자(10/27 로컬 통합본): 백엔드 테스트 **351개**·프론트 테스트 **34개** 모두 통과, CI 가 둘 다 돌린다(#130).
> 체험 계정 **100명이 동시에** 들어와 지출 → 판정 → 사유 → 최종 판정까지 **7.5초, 실패 0**(로컬 서버 기준 — 배포 서버 수치가 아니다).
> 관리자 → AI 사용량 화면(모델별 사용량, 기능별 끄기)도 질문이 오면 보여 준다.

## 예상 질문과 답

> 사실 확인한 것만 적었다. 모르는 건 모른다고 하고, 약점은 인정하고 계획을 말한다(9월과 같음).
> **질의응답은 3분** — 질문 서너 개면 끝난다. 답 하나는 **30초 안**, 첫 문장에 결론(「아닙니다」「받지 못합니다」)을 말하고 근거는 한 문장만.
> 화면이 필요한 질문(업적·알 개봉·AI 사용량)은 조작자가 미리 열어 둔 탭으로 바로 넘긴다.

**「AI 가 판정하나요?」**
> 아닙니다. 판정은 하루 예산과 비교하는 규칙이 합니다. AI 는 큰 지출에 이유를 묻는 문구를 만들고, 글로 쓴 이유를 여섯 가지(경조사·갑작스러운 일·모임·배움·사고 싶어서·기타)로 분류합니다.

**「이유를 거짓으로 대면 보상을 더 받지 않나요?」**
> 받지 못합니다. 이유가 인정되면 판정 색은 완화되지만, 코인과 스탯은 그날 예산에서 **실제로 남긴 금액**으로만 계산합니다. 예산을 넘긴 날은 이유와 상관없이 보상이 없습니다.
> (사유 인정을 보상에도 반영할지는 아직 정하지 않은 설계 질문이다 — [judgment-flow Q1](judgment-flow.md). 물어보면 「일부러 반영하지 않았다」고 답한다.)

**「처음 쓰는 사람도 바로 판정을 받나요?」**
> 받습니다. 9월에는 지출이 다섯 건 쌓일 때까지 판정을 건너뛰었는데, 지금은 가입 설문(월 수입·평소 식비 등)으로 기준선을 미리 채워 첫 지출부터 판정합니다.

**「자동 연동은 왜 안 하나요?」**
> 금융 마이데이터는 인가가 필요해 학부 작품 범위를 벗어납니다. 그리고 수동 입력이라서 가능한 것도 있습니다 — 자동으로 들어온 거래에는 이유를 물을 사람이 그 자리에 없습니다.
> 입력 부담은 영수증 사진 인식과 자동 카테고리 분류로 줄였습니다.

**「AI 가 안 되거나 비용이 많이 들면요?」**
> 사유는 칩으로 답하면 AI 를 쓰지 않습니다. AI 가 실패하면 글은 낱말 규칙으로, 질문은 기본 문구로 이어집니다. 한도가 차면 「오늘 준비한 AI 사용량을 다 썼어요」 안내가 나가고, 관리자 화면에서 기능별로 끌 수 있습니다. 대회 기간에는 유료 요금제로 돌리기로 했습니다.

**「개인정보는요?」**
> 비밀번호는 BCrypt 로 해시해 저장합니다. 체험 계정은 이메일·이름을 받지 않습니다. 탈퇴하면 30일 뒤 모든 기록을 지웁니다.
> AI 에는 이름이나 이메일을 보내지 않고, 지출 품목·금액·사용자가 쓴 이유·펫 이름·펫과 나눈 대화·영수증 사진만 보냅니다. 이메일 로그인은 연속으로 틀리면 잠깁니다(#137).

**「동시에 많이 들어오면 버티나요?」**
> 로컬에서 체험 계정 100명이 동시에 들어와 판정까지 하는 시험을 했고, 7.5초 안에 실패 없이 끝났습니다. 앞선 부하 시험에서는 동시 로그인 때 DB 연결이 묶이는 문제를 찾아 고쳤습니다(#135).
> (배포 서버 사양에서는 아직 재지 않았다 — 물어보면 그렇게 답한다.)

**「펫 키우기는 다른 금융 앱에도 있는데요?」**
> 차별점은 캐릭터가 아니라 **자라게 하는 기준**입니다. 출석이나 걸음 수가 아니라 그날 예산에서 아낀 금액이 스탯이 됩니다.

**「실제 사용자에게 효과가 있었나요?」**
> 장기 사용자 검증은 하지 못했습니다. 이번 경진대회 체험 기록과, 학기·방학처럼 씀씀이가 바뀌는 시기를 반영하는 것이 다음 과제입니다.

1. MySQL 켜기 → 저장소 루트 `.env` 확인(DB 비밀번호·Gemini 키).
2. 백엔드: `cd backend` → `.\gradlew.bat bootRun --args="--vori.ai-judge.open-hour=0"` (무대 규칙 2의 서버 쪽).
3. 프론트: `frontend/.env.local` 에 `REACT_APP_AI_ACTIVE_FROM_HOUR=0` → `npm start`.
4. 시연 계정: `python scripts/demo_seed.py` (전날), 발표 날 아침 `--checkin`.
5. 인터넷이 끊겨도 1~9번은 된다 — Gemini 가 필요한 건 질문 문구(기본 문구로 대신)와 영수증뿐이다.

### 11/11 경진대회 — 노트북을 서버로, 관람객은 같은 와이파이의 휴대폰으로

```
노트북 IP 확인      ipconfig → 무선 LAN 의 IPv4 (예: 172.16.106.239)
백엔드              set CORS_ALLOWED_ORIGINS=http://localhost:3000,http://<IP>:3000
                    set GUEST_DAILY_LIMIT=300
                    .\gradlew.bat bootRun --args="--vori.ai-judge.open-hour=0"
프론트              set REACT_APP_API_BASE=http://<IP>:8080/api
                    set REACT_APP_AI_ACTIVE_FROM_HOUR=0
                    npm start
QR 코드 주소        http://<IP>:3000
```

- **10/27 확인한 것**(통합본, 노트북 IP 172.16.106.239): 화면 번들에 그 IP 의 API 주소가 들어가고, 서버가 그 출처를 CORS 로 허용하고,
  쿠키가 유지돼 체험하기 → 홈 → 지출 → 판정이 그 IP 로 모두 200. 같은 IP·다른 포트라 쿠키(SameSite=Lax)가 그대로 간다.
- **확인 못 한 것 — 대회 전에 현장에서 꼭 본다**
  - 휴대폰이 노트북에 닿는지: Windows 방화벽에서 **3000·8080 포트 인바운드 허용**이 필요하다(노트북 주인이 직접 설정).
  - 대회장 와이파이가 **기기끼리 통신을 막는지**(학교·공용 와이파이에 흔하다). 막히면 노트북과 휴대폰을 **휴대폰 핫스팟** 하나에 같이 붙이거나,
    부스의 노트북·태블릿에서 직접 체험하게 한다.
  - IP 는 와이파이에 다시 붙을 때마다 바뀔 수 있다 — 바뀌면 프론트를 다시 켜고(주소가 빌드에 들어간다) QR 도 다시 만든다.
  - 노트북 절전·화면 꺼짐을 끈다. 전원 어댑터를 꽂는다.
- 대회가 끝나면 체험 계정을 지운다 — [`final-demo-plan.md`](final-demo-plan.md) 3절의 정리 SQL.
