# 중간발표 시연 계획

> 9/30(수) 중간발표에서 VORI 를 5분 안에 보여주기 위한 각본, 연동 우선순위, 계정 세팅 절차.
> 작성 2026-09-08 · 황채린

## 왜 이 문서가 필요한가

백엔드 도메인은 전부 구현됐지만 화면에 붙은 건 일부다. 남은 6개(가구·목표·영수증·예산·칭호·테마)가 전부 똑같은 무게로 보이면 무엇부터 붙일지 알 수 없고, 발표 직전에 **"다 반쯤 된" 상태**가 된다. 반쯤 된 기능 여섯 개보다 완전히 되는 기능 네 개가 발표에서 훨씬 강하다.

각본을 먼저 정하면 우선순위가 자동으로 나온다 — **각본에 나오는 화면이 곧 필수**다.

## 1. 골든 패스

VORI 의 핵심 루프는 이거다.

```
아껴서 → 코인 벌고 → 펫 키우고 방 꾸며서 → 분양해서 → 더 좋은 알 산다
```

이 한 바퀴가 전부 보이는 동선이 하나 있다.

### 설계 원칙

**무대에서 하는 동작은 전부 "임계값을 넘는 순간" 이어야 한다.**

사전 세팅을 임계값 **직전**에서 멈춰두면, 발표 중에 누르는 버튼마다 무언가 터진다.
지출 10건을 무대에서 입력할 수는 없지만, 9건까지 채워두고 **10번째를 무대에서 누르면** 칭호가 눈앞에서 획득된다.

### 동선

| # | 무대 동작 | 화면에서 터지는 것 | 그러려면 사전에 |
|---|---|---|---|
| 1 | **큰 지출 1건 등록** (축의금 20만원) | **RED 판정** + **"기록의 시작" 칭호 획득** + AI 가 이유를 물음 | 지출을 **9건**까지만 (조건이 10건) |
| 2 | **"경조사였다" 고 답변** | **RED → GREEN 완화 + 코인 +100 + 펫 스탯 +10** ⭐ | — |
| 3 | 칭호 화면 열기 | 획득 목록 + 미획득 진행률 바 | — |
| 4 | 가구 상점 열기 | **아까 잠겨 있던 스터디 테마가 풀려 있음** | 1번에서 딴 칭호가 해금 조건 |
| 5 | **스터디 가구 2종** 사서 배치 | **스터디 세트 발동 (2/2, +15%)** | 스터디는 잠긴 상태여야 함 |
| 6 | 펫 분양 | 세트 보너스 얹힌 분양가 · **"첫 분양" 칭호** | 펫이 ADULT |
| 7 | 알 구매 → 개봉 | 가챠 연출 · 새 펫 등장 | 코인 충분 · **펫이 없는 상태**(6번 직후) |

### 이 각본에는 산이 둘 있다

**① 1~2번 — VORI 가 무엇인지 보여주는 장면**

지출 한 건으로 **RED 판정 · AI 질문 · 칭호 획득**이 한꺼번에 일어나고, 답변 하나로 **판정이 뒤집히며 펫이 자란다.** "지출한 이유를 묻는 가계부" 라는 소개가 화면으로 증명되는 자리다.

실측된 실제 Gemini 질문:
> *"평소보다 축의금을 넉넉히 내셨는데, 혹시 정말 소중한 분의 특별한 경사가 있으셨나요?"*

**② 4~5번 — 칭호가 상점을 여는 장면**

1번에서 딴 칭호가 4번에서 잠금을 풀고, 그 풀린 가구를 5번에서 사서 세트를 발동시킨다. **칭호 → 해금 → 구매 → 세트**가 하나의 사슬이다.

- 발표 시작 전 상점을 미리 한 번 열어 **"스터디 테마는 잠겨 있죠"** 를 짚어두면 대비가 산다.
- 우드 가구는 2/3 로 미발동인 채 남겨둔다 — 발동한 스터디와 나란히 보이면 조건이 무엇인지 설명 없이 이해된다.

### 6번 → 7번 순서를 지킬 것

펫을 보유한 채로 알을 개봉하면 **409** 가 뜬다(`"먼저 키우던 펫을 분양해주세요"`). 한 번에 한 마리만 키우는 구조라 그렇다. **반드시 분양 먼저, 개봉 나중.**

### ⚠️ AI 판정은 저녁 8시부터 열린다 — 발표 전에 반드시 조치할 것

`WalletPage` 의 판정 버튼과 `/wallet/analysis` 페이지는 **20시 이후에만** 열린다(1학기 4차 회의에서 정한 주작 방지 규칙). **낮에 하는 발표에서는 1~2번을 그대로 보여줄 수 없다.**

시각을 설정으로 뺐으므로 시연 전에 이렇게 둔다.

```
frontend/.env.local
REACT_APP_AI_ACTIVE_FROM_HOUR=0
```

`frontend/.env.example` 을 복사해 쓰면 된다. `.env.local` 은 git 에 올라가지 않으므로 **발표용 노트북에서 직접 만들어야 한다.** 운영 기본값은 20 이고, 시연이 끝나면 되돌린다.

## 2. 영수증 OCR — 병렬로 돌린다

영수증 인식은 응답까지 **18~31초** 걸린다(4.4MB 사진 실측 30.5초). 무대에서 멀뚱히 기다리면 죽는 시간이다.

**발표를 시작하면서 업로드를 걸어두고, 위 1~4번을 진행한 뒤 5번 직전에 결과를 확인한다.**

"AI 가 읽는 동안 다른 걸 보여드릴게요" 는 무대 연출이 아니라 **실제 사용자가 겪을 UX** 이기도 하다. 숨길 게 아니라 그렇게 설계됐다고 말하면 된다.

> ✅ `f5a78ac`(multipart 상한 10MB)가 PR #15 로 main 에 들어와 조건이 풀렸다. 4.4MB 휴대폰 사진 실측 통과.

영수증은 **기술난이도 배점(20%)에서 가장 강한 카드**다. AI 이미지 인식은 다른 팀이 쉽게 흉내내기 어렵다. 시간이 부족하더라도 이건 넣는 쪽이 낫다.

## 3. 연동 우선순위

각본을 기준으로 자른 것이다. API 명세는 [`api-integration.md`](api-integration.md) 참조.

### 현재 연동 상태 (2026-09-09 실측)

앱을 실제로 띄워 화면을 눌러 가며 네트워크 호출을 확인했다. 추정이 아니라 실측이다.

**✅ 이미 붙어 있다 — 핵심 루프는 돌아간다**

| 화면 | 실제로 호출하는 API |
|---|---|
| 홈 대시보드 | `users/me/home` · `pets/active` · `daily-reports/today` · `ledger` |
| 가계부 | `ledger` · **`inquiries`** (AI 질문·답변까지 연결됨) |
| 상점 — 알 | `eggs/products` · `eggs` · `users/me` |
| 마이룸 — 펫 | `pets` · `pets/active` |

지출 → 신호등 → AI 질문 → 펫 성장으로 이어지는 **핵심 루프는 화면에 이미 있다.** 알 확률도 `EggGrade` 값(S1/A5/B24/C70)이 그대로 나온다.

**❌ 아직 목업이거나 없다**

| | 실제 화면 상태 |
|---|---|
| **칭호** | 목업 — "첫 지출 기록 / 한 주 예산 지키기 / 카페 지출 줄이기". 우리 칭호 13개가 아니다. 사이드바 `업적/칭호` 버튼은 이동하지 않는다 |
| **가구** | 목업 — "초록 소파 · 화분 · 스탠드 · 체크 러그". `FurnitureCatalog` 에 없는 항목들이고 `/api/furniture` 호출이 없다 |
| **테마** | 없음. 마이룸의 "배경 변경(기본 방/노란 방…)" 은 우드·코지·스터디와 다른 개념이다 |
| **예산** | 화면에 *"예산 설정 기능을 준비 중이에요"* 라고 표시된다 |
| **목표 · 영수증** | 진입점 없음 |

### 🚨 지금 상태로는 각본 3~5번이 불가능하다

| # | 무대 동작 | 가능? |
|---|---|---|
| 1 | 큰 지출 등록 → RED → AI 질문 | ✅ 가계부에 `inquiries` 가 붙어 있다 |
| 2 | 답변 → 판정 완화 + 인정 보상 | ✅ |
| 3 | 칭호 화면 | ❌ 목업 |
| 4 | 상점에서 스터디 해금 확인 | ❌ 가구 상점 자체가 없음 |
| 5 | 스터디 가구 구매·배치 → 세트 발동 | ❌ |
| 6 | 펫 분양 | ✅ |
| 7 | 알 개봉 | ✅ |

**다행히 1~2번(VORI 를 VORI 답게 만드는 장면)은 이미 붙어 있다.** 안 되는 건 4~5번의 인과 사슬이다.

### 그래서 이 순서로

| 순위 | 대상 | 왜 |
|---|---|---|
| **1** | **칭호** `GET /api/titles` · `PUT /api/titles/active` | **화면을 새로 만들 필요가 없다.** 홈 대시보드에 "최근 업적" 자리가 이미 있으므로 목업 데이터를 응답으로 바꾸기만 하면 된다. 비용 대비 효과가 가장 크다 |
| **2** | 가구 상점 `GET /api/furniture/products` · `POST /api/furniture/buy` | 화면 신규. 각본 3번 |
| **3** | 마이룸 배치 `GET /api/furniture` · `PATCH /api/furniture/{id}/place` | 각본 4번 |
| **4** | 테마 `GET /api/themes` | 가구 화면에 붙는 표시. 2·3 이 있어야 의미가 생긴다 |
| **5** | 영수증 `POST`/`GET /api/receipts` | `f5a78ac` 가 main 에 들어와 조건이 풀렸다. 4.4MB 휴대폰 사진 실측 통과. **기술난이도 배점에서 가장 강한 카드** |
| 6 | 월 예산 `GET`/`PUT /api/budgets` | 각본에 안 나옴. 화면은 단순함 |
| 7 | 절약 목표 `/api/goals` | 각본에 안 나옴. 진행률이 쌓이려면 시간이 필요 |

**1~4 는 9/30 전에 반드시**, 5 는 넣는 쪽이 강하고, 6~7 은 여유가 되면.

## 4. 시연 계정 세팅

발표 당일 새 계정으로 처음부터 하면 코인 0 · 펫 INFANT 라 아무것도 보여줄 수 없다.
**세팅 스크립트를 한 번 실행하면 각본이 성립하는 상태가 그대로 만들어진다.**

```
python scripts/demo_seed.py              발표용 계정 생성
python scripts/demo_seed.py --rehearse   세팅 + 무대 7단계를 실제로 눌러보는 리허설
```

`--rehearse` 는 세팅 상태를 소모한다(10번째 지출·배치·분양·개봉을 실제로 해버린다).
**발표용 계정은 `--rehearse` 없이** 만들 것. 실행 끝에 로그인 정보가 출력된다.

### 코인과 스탯이 생기는 공식

| 값 | 계산 |
|---|---|
| 절약액 | 직전까지의 평균 − 이번 지출 |
| 코인 | 절약액 ÷ 10 |
| 펫 스탯 | 절약액 ÷ 1,000 |

**큰 지출을 먼저 넣어 평균을 올리고 그다음 작은 지출**을 넣으면 코인과 스탯이 한 번에 확보된다. 스크립트가 넣는 9건이 이 구조다.

| # | 품목 | 금액 | 절약액 |
|---|---|---|---|
| 1 | 한 달 장보기 | 180,000 | — (기준선을 올리는 지출) |
| 2 | 편의점 도시락 | 4,500 | 175,500 |
| 3 | 아메리카노 | 2,000 | 142,900 |
| 4 | 삼각김밥 | 1,400 | 114,920 |
| 5 | 학식 정식 | 5,000 | 88,336 |
| 6 | 떡볶이 배달 | 3,200 | 72,468 |
| 7 | 자판기 커피 | 1,400 | 59,775 |
| 8 | 샌드위치 | 4,500 | 44,720 |
| 9 | 김밥천국 | 3,500 | 36,776 |

지출은 전부 **식비 계열(카테고리 2~6, statType=ENERGY)** 을 쓴다. EMA 기준선이 statType 별로 따로 관리되므로 다른 계열을 섞으면 절약액 계산이 어긋난다.

### 세팅 후 상태 (2026-09-08 실측)

| 항목 | 값 |
|---|---|
| 지출 | **9건** (10번째가 무대용) |
| 보유 코인 | **63,537** (스터디 가구 15,000 + 알 2,500 쓰고도 충분) |
| 펫 | 강아지 · **ADULT** · 스탯 730 |
| 획득 칭호 | 절약 새싹 · 절약 중수 |
| 미획득 | 기록의 시작 **9/10** · 절약 고수 **73%** ← 진행률 바 시연용 |
| 테마 | 우드 **2/3 미발동** · 코지 해금 · **스터디 잠김** |

**스터디가 잠겨 있어야 4~5번 장면이 산다.** 세팅 중에 지출을 10건 넘기면 각본이 무너진다.
스크립트가 이 조건을 전부 검사하고, 하나라도 어긋나면 FAIL 을 띄운다.

### 리허설 결과 (2026-09-09, 32/32 통과)

무대 7단계를 API 로 실제로 눌러 확인했다.

- 축의금 20만원 → **RED (z = 2.263)** + **"기록의 시작" 칭호** 동시 획득
- 실제 생성된 Gemini 질문 — *"평소보다 축의금을 넉넉히 내셨는데, 혹시 정말 소중한 분의 특별한 경사가 있으셨나요?"*
- "경조사였다" 답변 → **RED → GREEN**, 코인 **+100**, 펫 스탯 **+10**
- 상점에서 **스터디 테마 잠금 풀림** (1번 칭호의 결과)
- 스터디 가구 2종 배치 → **세트 발동 2/2** (우드는 2/3 로 미발동)
- 분양가 **스탯 740 × 10 × 1.245 = 9,213 코인** (개별 9.50% + 스터디 세트 15.00%)
- **"첫 분양" 획득** → 알 개봉 성공(분양 후라서 가능)

| **IPv6 만 잡히는 네트워크** | `build.gradle` 에 `-Djava.net.preferIPv4Stack=true` 를 박아뒀다 |
| AI 판정 버튼이 안 눌림 | `.env.local` 의 `REACT_APP_AI_ACTIVE_FROM_HOUR=0` 을 확인 |
| 인터넷/서버 문제 | 각 단계 화면 캡처를 미리 떠둔다 |
| 영수증이 실패하거나 느림 | 결과 화면 캡처를 준비. 넘어가고 나중에 언급 |
| 가챠에서 C등급만 나옴 | 확률이라 어쩔 수 없다. 등급표를 같이 보여주며 설명 |
| 시연 계정이 망가짐 | **예비 계정을 하나 더 세팅해 둔다** |

### 🔴 Gemini 무료 한도가 생각보다 훨씬 낮다 — 가장 큰 시연 위험

2026-09-09 에 429 응답 원문에서 확인한 실측값이다.

```json
"quotaId":    "GenerateRequestsPerDayPerProjectPerModel-FreeTier",
"quotaValue": "20",
"model":      "gemini-3.6-flash",
"retryDelay": "33s"
```

**`generateContent` 무료 한도가 20건이다.** 블로그 요약에 흔히 나오는 "1,500 requests/day" 와 다르다 — 모델·메트릭마다 별도 쿼터가 걸린다. 실측을 믿을 것.

**시연 1회가 `generateContent` 2건을 쓴다** (질문 생성 + 답변 분류). 즉 **리허설 10번이면 하루치가 사라진다.**

> ⚠️ 영수증 OCR 도 같은 메트릭을 쓴다. 시연에 영수증을 넣으면 회당 3건이다.
> 임베딩(`gemini-embedding-001`)은 다른 모델이라 별도 쿼터다 — 서버 재시작은 이 한도와 무관하다.

**대응**

| | 방법 | 비고 |
|---|---|---|
| 1 | **발표 당일에는 리허설하지 않는다** | 전날까지 끝낸다. 당일 아침 "혹시 몰라서" 한 번이 본 발표를 죽인다 |
| 2 | **1·2번 장면 화면 녹화를 미리 떠둔다** | 429 가 나면 녹화로 대체한다. 가장 확실한 보험 |
| 3 | 시연 직전 남은 횟수를 확인한다 | https://ai.dev/rate-limit |
| 4 | 팀원별 API 키로 나눠 쓴다 | 키는 Google 계정마다 별도 쿼터다. 리허설과 본 발표에 다른 키를 쓰면 본 발표분이 남는다 |

**1번과 2번을 함께 한다.** 운영으로 막고, 그래도 터지면 녹화로 넘어간다.

> ⚠️ 1학기 회의록의 학과 지원 항목 'AI 구독 요금 3개월' 은 **코딩용 AI 구독**이지
> Gemini API 크레딧이 아니다. 이 문제에는 쓸 수 없다.
> 유료 티어로 올리려면 Google AI Studio 에 결제 수단을 연결해야 하는데, 학부 작품에
> 개인 카드를 거는 건 권하지 않는다.
