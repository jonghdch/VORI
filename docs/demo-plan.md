## 왜 이 문서가 필요한가

백엔드 도메인은 전부 구현됐지만 화면에 붙은 건 일부다. 남은 6개(가구·목표·영수증·예산·칭호·테마)가 전부 똑같은 무게로 보이면 무엇부터 붙일지 알 수 없고, 발표 직전에 **"다 반쯤 된" 상태**가 된다. 반쯤 된 기능 여섯 개보다 완전히 되는 기능 네 개가 발표에서 훨씬 강하다.

각본을 먼저 정하면 우선순위가 자동으로 나온다 — **각본에 나오는 화면이 곧 필수**다.

## 1. 골든 패스

VORI 의 핵심 루프는 이거다.

```
아껴서 → 코인 벌고 → 펫 키우고 방 꾸며서 → 분양해서 → 더 좋은 알 산다
```

이 한 바퀴가 전부 보이는 동선이 하나 있다.

### 설계 원칙

**무대에서 하는 동작은 전부 "임계값을 넘는 순간" 이어야 한다.**

사전 세팅을 임계값 **직전**에서 멈춰두면, 발표 중에 누르는 버튼마다 무언가 터진다.
지출 10건을 무대에서 입력할 수는 없지만, 9건까지 채워두고 **10번째를 무대에서 누르면** 칭호가 눈앞에서 획득된다.

### 동선

| # | 무대 동작 | 화면에서 터지는 것 | 그러려면 사전에 |
|---|---|---|---|
| 1 | **큰 지출 1건 등록** (**결혼식 축의금** 20만원) | **RED 판정** + **"기록의 시작" 칭호 획득** + AI 가 이유를 물음 | 지출을 **9건**까지만 (조건이 10건) |
| 2 | **"경조사였다" 고 답변** | **RED → GREEN 완화 + 코인 +100 + 펫 스탯 +10** ⭐ | — |
| 3 | 칭호 화면 열기 | 획득 목록 + 미획득 진행률 바 | — |
| 4 | 가구 상점 열기 | **아까 잠겨 있던 스터디 테마가 풀려 있음** | 1번에서 딴 칭호가 해금 조건 |
| 5 | **스터디 가구 2종** 사서 배치 → **컴퓨터를 펫 옆 빈 곳으로 드래그** | **스터디 세트 발동 (2/2, +15%)** | 스터디는 잠긴 상태여야 함 |
| 6 | 펫 분양 | 세트 보너스 얹힌 분양가 · **"첫 분양" 칭호** | 펫이 ADULT |
| 7 | 알 구매 → 개봉 | 누르면 즉시 결과 카드 출력 · 새 펫 등장 | 코인 충분 · **펫이 없는 상태**(6번 직후) |

### 🚨 무대에서 입력할 문구는 **"결혼식 축의금"** 이다 — "축의금" 이라고만 쓰면 각본이 죽는다

2026-09-16 에 앱을 띄워 직접 타이핑해 보고 찾았다. **한 단어 차이로 1·2번이 통째로 무너진다.**

```
축의금          →  고정비·공과금 (ENDURANCE)   표본 0건  →  무조건 GREEN, z = null
결혼식 축의금     →  식비·외식 (ENERGY)         표본 9건  →  RED z = 2.263  ✅
```

시드가 깔아 두는 지출 9건은 전부 **식비(ENERGY)** 다. 그런데 자동 분류기가 `축의금` 을
**공과금(ENDURANCE)** 으로 보낸다. ENDURANCE 는 표본이 0이라 `sample_count < 5` 규칙에 걸려
**신호등이 무조건 GREEN** 이 되고, RED 가 아니니 **AI 질문도 안 나오고 칭호 연출도 없다.**

`demo_seed.py --rehearse` 에서는 이 문제가 안 보인다. 스크립트가 API 를 직접 호출하면서
`categoryId: 2` 를 지정하기 때문이다. **사람이 화면에서 타이핑할 때만 드러난다.**

실측한 다른 후보들(모두 식비·외식으로 분류됨):

```
결혼식 축의금   0.652      경조사비   0.716      회식비   0.829
```

> 무대 문구를 바꾸려면 **반드시 화면에서 한 번 타이핑해 카테고리를 확인할 것.**
> 카테고리가 식비 계열이 아니면 그 항목은 쓸 수 없다.

### 이 각본에는 산이 둘 있다

**① 1~2번 — VORI 가 무엇인지 보여주는 장면**

지출 한 건으로 **RED 판정 · AI 질문 · 칭호 획득**이 한꺼번에 일어나고, 답변 하나로 **판정이 뒤집히며 펫이 자란다.** "지출한 이유를 묻는 가계부" 라는 소개가 화면으로 증명되는 자리다.

질문 문구는 **매번 새로 생성된다.** 프롬프트 중립화(PR #23) 이후 9/17 에 두 번 실측한 질문:
> *"이번 결혼식 축의금은 평소보다 지출이 컸는데, 어떤 일이었는지 가볍게 메모해 줄래?"*

두 번 모두 같은 문구였지만 보장되지 않는다. **대본에 질문을 고정해 적지 말고, 화면에 뜬 질문을 그대로 읽는다.**

**② 4~5번 — 칭호가 상점을 여는 장면**

1번에서 딴 칭호가 4번에서 잠금을 풀고, 그 풀린 가구를 5번에서 사서 세트를 발동시킨다. **칭호 → 해금 → 구매 → 세트**가 하나의 사슬이다.

- 발표 시작 전 상점을 미리 한 번 열어 **"스터디 테마는 잠겨 있죠"** 를 짚어두면 대비가 산다.
- 우드 가구는 2/3 로 미발동인 채 남겨둔다 — 발동한 스터디와 나란히 보이면 조건이 무엇인지 설명 없이 이해된다.

### 1·2번 화면 조작 순서 (2026-09-17 실측)

판정 결과와 보상은 **입력한 화면에 바로 뜨지 않는다.** 어디로 가서 무엇을 가리킬지 정해 두지 않으면 무대에서 헤맨다.

```
1  가계부 → [+ 지출 추가] → [+ 지출 추가하기]
   내역 "결혼식 축의금" · 금액 200000     카테고리 칩이 '식비 · 외식' 인지 확인
   [다음 단계]                          ← 여기서 저장된다. 판정·칭호·질문 생성이 이 순간 시작
   [완료하기] → 홈으로 이동
   홈 아래 "최근 업적"                   → '기록의 시작 — 완료'   (팝업 알림은 없다)
   상단 [가계부] → 월간 지출 내역 표      → 결혼식 축의금 행에 '비합리적' 빨간 배지 = RED
   AI 소비 판정 카드                     → "오늘 미답변 질문 1건" → [판정 시작하기]
   질문 화면(/wallet/analysis)          → 내역·금액 카드 아래 "Q. …" 질문

2  질문 아래 입력칸에 답변 → [완료]
   "저장 중…" 몇 초 → 가계부 화면 맨 위로 돌아온다
   월간 지출 내역 표                     → 같은 행이 '합리적' 으로 바뀜 = GREEN
```

- **질문 생성은 빠르다.** 저장 직후 확인 화면에 있는 동안 이미 만들어져 있었다. 판정 카드가 "미답변 질문 0건" 이면 잠시 뒤 가계부를 다시 연다(자동 갱신 안 됨).
- **보상(+100 코인 · +10 스탯)은 이 화면들에 표시되지 않는다.** 코인은 **상점 머리의 "보유 코인"**(63,537 → 63,637), 스탯은 **마이룸 "스탯 합 740" · 분양 버튼 "7,400 코인~"** 에서 보인다. 4번(상점)·5~6번(마이룸)에서 짚는다.
- 홈 말풍선에 *"저녁 8시에 같이 돌아봐요!"* 가 뜬다. 판정 시각을 `.env.local` 로 풀어 둔 시연에서는 사실과 다르지만 문구가 고정이라 바뀌지 않는다. 짚지 말고 넘어간다.

### 5번 — 배치하고 나면 컴퓨터를 펫 옆으로 옮길 것

2026-09-17 화면 리허설에서 찾았다. "배치하기" 를 누르면 가구가 카테고리별 기본 자리에 놓이는데,
**컴퓨터가 펫 바로 밑에 놓여 펫에 가려 거의 안 보인다.** 빈자리 찾기가 가구끼리만 피하고 펫은 피하지 않기 때문이다.

무대에서는 **배치 직후 방으로 올라가 컴퓨터를 펫 옆 빈 곳으로 드래그**한다. 드래그한 자리는 서버에 저장된다.

세트 발동은 방 카드 오른쪽 위 칩(**"스터디 2/2 발동 +15%"**)으로 보인다 — PR #27.
머지 전 화면에는 세트 표시가 없어 말로 설명해야 한다(서버에서는 발동한다).

### 6번 → 7번 순서를 지킬 것

펫을 보유한 채로 알을 개봉하면 **409** 가 뜬다(`"먼저 키우던 펫을 분양해주세요"`). 한 번에 한 마리만 키우는 구조라 그렇다. **반드시 분양 먼저, 개봉 나중.**

### ⚠️ AI 판정은 저녁 8시부터 열린다 — 발표 전에 반드시 조치할 것

`WalletPage` 의 판정 버튼과 `/wallet/analysis` 페이지는 **20시 이후에만** 열린다(1학기 4차 회의에서 정한 주작 방지 규칙). **낮에 하는 발표에서는 1~2번을 그대로 보여줄 수 없다.**

시각을 설정으로 뺐으므로 시연 전에 이렇게 둔다.

```
frontend/.env.local
REACT_APP_AI_ACTIVE_FROM_HOUR=0
```

`frontend/.env.example` 을 복사해 쓰면 된다. `.env.local` 은 git 에 올라가지 않으므로 **발표용 노트북에서 직접 만들어야 한다.** 운영 기본값은 20 이고, 시연이 끝나면 되돌린다.

> ✅ **2026-09-17 플랜 A 로 확정했다.** PR #25 로 가구 상점·마이룸 배치가 붙었고, 최신 main 에서

> 이 절은 판단 근거로 남겨 둔다.

### 언제 이걸로 갈아타나

각본 4·5(가구 상점·마이룸 배치)는 프론트가 아직 없고, 2026-09-10 기준 **담당자도 정해지지 않았다.**
발표 직전까지 "곧 붙는다" 를 붙들고 있으면 리허설을 못 하고, 리허설 못 한 각본은 무대에서 깨진다.

**마지노선은 9/20(일).** 그날까지 가구 상점과 마이룸 배치가 화면에서 돌지 않으면 미련 없이 플랜 B 로 간다.

```
9/20(일)   플랜 A / B 확정        ← 여기서 결정하고 되돌아보지 않는다
9/27(토)   리허설 (확정된 각본으로)
9/30(수)   중간발표
```

### 원칙 — 뺀 자리를 다른 기능으로 때우지 않는다

각본 4·5 를 빼면 1분 30초쯤 빈다. 이 자리를 예산·목표 같은 다른 기능으로 채우면 5분이 산만해지고,
어느 것도 제대로 안 보인다. **반쯤 된 기능 여섯 개보다 완전히 되는 기능 네 개가 강하다** 는
이 문서의 원칙이 여기서도 똑같이 적용된다.

대신 **VORI 의 유일한 차별점을 한 번 더, 반대 방향으로** 보여준다.

시장 리서치의 결론이 *"펫 육성은 차별점이 아니다. 지출한 이유를 묻고 판정에 반영하는 것이 유일한 차별점"* 이었으므로,
가구(=펫 육성 곁가지)를 빼는 것은 오히려 **초점을 선명하게 만든다.**

| 4:40 | 마무리 | — |

### 2:00 대조 장면이 이 플랜의 핵심이다

원래 각본은 **인정되는 경우만** 보여줬다. 그래서 "AI 가 이유를 본다" 는 주장의 절반만 증명됐다.
같은 20만원인데 결과가 갈리는 걸 나란히 놓으면, 말로 설명할 필요 없이 증명된다.

> 이유가 있으면 GREEN 이 되고 펫이 자란다.
> 이유가 없으면 RED 그대로고 아무것도 얻지 못한다.

그리고 이 장면이 있어야 3:10 분양 멘트가 **설명이 아니라 이미 증명된 사실**이 된다.

#### 실측 검증 (2026-09-10)

무대에서 "그냥 샀어요" 라고 답했는데 AI 가 관대하게 인정해버리면 시연의 신뢰도가 통째로 날아간다.
그래서 각본을 확정하기 전에 실제로 돌려봤다.

| 답변 | 신호등 | 분류 | 코인 | 스탯 |
|---|---|---|---|---|
| "그냥 갖고 싶어서 샀어요" | RED → RED | `IMPULSE` | +0 | +0 |
| "스트레스 받아서 질렀어요" | RED → RED | `IMPULSE` | +0 | +0 |
| "세일하길래 그냥 샀어요" | RED → RED | `IMPULSE` | +0 | +0 |

셋 다 **`ETC` 폴백이 아니라 실제로 `IMPULSE` 로 분류**됐다(서버 로그에 분류 실패 0건).
특히 `SELF_INVEST` 로 샐 위험이 컸던 *"스트레스 받아서"* 도 깐깐하게 잘렸다.

판정 매핑은 `AiInquiryService.computeSignalFinal` 참조.

```
CEREMONY · EMERGENCY · SELF_INVEST  →  GREEN + 코인 100 + 스탯 10
SOCIAL                              →  GRAY,  보상 없음
IMPULSE · ETC                       →  원래 신호 유지, 보상 없음
```

> ⚠️ **무대에서 나올 질문 문구는 매번 새로 생성되고, 우리가 통제하지 못한다.**
> 검증 중에 *"혹시 어떤 특별하고 마음 설레는 지출이었는지 들려주실 수 있나요?"* 같은 문구가 나왔다.
> 충동구매에 이렇게 물으면 **VORI 가 묻기도 전에 편들어주는** 것처럼 보여 대조 장면의 메시지가 약해진다.
> 분류 프롬프트를 중립화하는 작업이 별도로 필요하다.

### 3:10 분양 멘트 — 가구가 빠진 자리를 이렇게 채운다

세트 보너스를 못 쓰므로 분양가 설명을 바꾼다. 없어진 걸 변명하지 말고 **더 순수한 주장으로** 바꾼다.

> "VORI 의 펫 분양가는 임의로 정해지지 않습니다.
> 제가 그동안 절약한 금액과, 방금 AI 에게 합리적이라고 인정받아 얻은 스탯이
> 정확히 비례해서 코인으로 환산됩니다."

### 시간이 남으면 쓰는 예비 카드 — 어드민 판정 규칙

`/admin/rationality-rules` 에서 `z_red` · `z_green` 을 조정할 수 있다(이미 화면에 붙어 있다).
임계값을 낮추고 같은 지출을 다시 넣으면 판정이 바뀐다.

**"판정 규칙이 하드코딩이 아니라 운영 가능한 설정"** 을 30초에 보여줄 수 있어
기술난이도 배점(20%)을 노리는 자리다. 다만 5분이 빠듯하면 **가장 먼저 버릴 카드**다.

### 세팅 스크립트 변경

| | 플랜 A | 플랜 B |
|---|---|---|
| 지출 9건 | 유지 | 유지 |

| ADULT 펫 보정 | 유지 | 유지 |

`demo_seed.py --plan-b` 로 넣으면 플랜 A 세팅도 그대로 남는다.

### 리스크 — 플랜 B 는 Gemini 를 2.5배 쓴다

시연 1회에 드는 `generateContent` 건수다. 한도는 하루 20건(5절).

```
플랜 A   질문 1 + 답변 분류 1              = 2건 → 리허설 10회
         영수증 포함                       = 3건 → 6회
플랜 B   질문 2 + 답변 분류 2 + 영수증 1    = 5건 → 4회
```

**리허설할 수 있는 횟수가 A 의 절반도 안 된다.** 한도가 언제 다시 차는지는 5절 "한도는 오후 4시에 찬다" 참조.

## 2. 영수증 OCR — 병렬로 돌린다

> 📝 이 절은 2026-09-10 에 두 번 고쳤다. 원래 *"업로드를 걸어두고 나중에 확인한다"* 고 적혀
> 있었는데 **화면에 업로드 진입점이 없어 불가능**했고(3절 표와 모순), 그래서 "올릴 수 없다" 로
> 고쳤다가 **같은 날 `209b570` 로 진입점을 붙여** 다시 가능해졌다.

```
백엔드   POST /api/receipts                동작 (4.4MB 휴대폰 사진 실측 통과)
프론트   WalletEntryPage  📷 영수증 사진으로 채우기      ✅ 209b570
         api/receipt.js   uploadReceipt · listReceipts · getReceipt
```

**왜 가구·마이룸보다 먼저 붙였나.** 영수증은 기술난이도 배점(20%)에서 가장 강한 카드다 —
AI 이미지 인식은 다른 팀이 쉽게 흉내내기 어렵다. 그런데 비용은 더 작았다.

| | 화면 규모 | 각본 기여 | 기술난이도 어필 |
|---|---|---|---|
| 가구 상점 + 마이룸 | 2화면 · 큼 | 각본 4·5 | 낮음 (게임 곁가지) |
| **영수증 업로드** | 1화면 · 작음 | 각본 0·5 | **가장 높음** |

### 무대에서 쓰는 법

인식은 응답까지 **6~13초** 걸린다(PR #26 이후 업로드 전에 긴 변 2048px 로 줄여 보낸다 —
실물 영수증 6.0초 · 합성 이미지 10.7~11.6초). 줄이지 않고 원본을 보내면 9~31초였다.
무대에서 멀뚱히 기다리면 죽는 시간이므로 **발표를 시작하면서 업로드를 걸어두고,
다른 장면을 진행한 뒤 마지막에 결과를 확인한다.**

"AI 가 읽는 동안 다른 걸 보여드릴게요" 는 무대 연출이 아니라 **실제 사용자가 겪을 UX** 이기도 하다.
숨길 게 아니라 그렇게 설계됐다고 말하면 된다.

인식 결과는 지출로 바로 저장되지 않고 **가계부 행에 채워지기만 한다.** 사용자가 확인·수정한 뒤
저장하는 흐름이라, 무대에서도 "AI 가 읽어 준 값을 사람이 확인한다" 로 설명하면 된다.

### 실측된 동작 (2026-09-10, 브라우저에서 직접)

```
성공         떡볶이 / 14,000 / 신용카드 로 행이 채워짐 · 카테고리도 '식비·외식' 자동 분류
영수증 아님   모든 값 null → "영수증을 읽지 못했어요" · 빈 행이 생기지 않음
10MB 초과    "사진이 너무 커요 (11.0MB)" — 서버에 가지도 않음
진행 중       버튼 비활성 + "10~15초쯤 걸려요"
```

> ⚠️ 영수증 날짜가 작성 중인 날짜와 다르면 **알려만 주고 날짜를 바꾸지 않는다.**
> 바꾸면 이미 입력한 다른 행들이 엉뚱한 날짜로 저장된다. 무대에서는 **오늘 날짜 영수증**을 쓸 것.

## 4. 시연 계정 세팅

발표 당일 새 계정으로 처음부터 하면 코인 0 · 펫 INFANT 라 아무것도 보여줄 수 없다.
**세팅 스크립트를 한 번 실행하면 각본이 성립하는 상태가 그대로 만들어진다.**

```
python scripts/demo_seed.py              발표용 계정 생성
python scripts/demo_seed.py --rehearse   세팅 + 무대 7단계를 실제로 눌러보는 리허설
```

`--rehearse` 는 세팅 상태를 소모한다(10번째 지출·배치·분양·개봉을 실제로 해버린다).
**발표용 계정은 `--rehearse` 없이** 만들 것. 실행 끝에 로그인 정보가 출력된다.

### 코인과 스탯이 생기는 공식

| 값 | 계산 |
|---|---|
| 절약액 | 직전까지의 평균 − 이번 지출 |
| 코인 | 절약액 ÷ 10 |
| 펫 스탯 | 절약액 ÷ 1,000 |

**큰 지출을 먼저 넣어 평균을 올리고 그다음 작은 지출**을 넣으면 코인과 스탯이 한 번에 확보된다. 스크립트가 넣는 9건이 이 구조다.

| # | 품목 | 금액 | 절약액 |
|---|---|---|---|
| 1 | 한 달 장보기 | 180,000 | — (기준선을 올리는 지출) |
| 2 | 편의점 도시락 | 4,500 | 175,500 |
| 3 | 아메리카노 | 2,000 | 142,900 |
| 4 | 삼각김밥 | 1,400 | 114,920 |
| 5 | 학식 정식 | 5,000 | 88,336 |
| 6 | 떡볶이 배달 | 3,200 | 72,468 |
| 7 | 자판기 커피 | 1,400 | 59,775 |
| 8 | 샌드위치 | 4,500 | 44,720 |
| 9 | 김밥천국 | 3,500 | 36,776 |

지출은 전부 **식비 계열(카테고리 2~6, statType=ENERGY)** 을 쓴다. EMA 기준선이 statType 별로 따로 관리되므로 다른 계열을 섞으면 절약액 계산이 어긋난다.

### 세팅 후 상태 (2026-09-08 실측)

| 항목 | 값 |
|---|---|
| 지출 | **9건** (10번째가 무대용) |
| 보유 코인 | **63,537** (스터디 가구 15,000 + 알 2,500 쓰고도 충분) |
| 펫 | 강아지 · **ADULT** · 스탯 730 |
| 획득 칭호 | 절약 새싹 · 절약 중수 |
| 미획득 | 기록의 시작 **9/10** · 절약 고수 **73%** ← 진행률 바 시연용 |
| 테마 | 우드 **2/3 미발동** · 코지 해금 · **스터디 잠김** |

**스터디가 잠겨 있어야 4~5번 장면이 산다.** 세팅 중에 지출을 10건 넘기면 각본이 무너진다.
스크립트가 이 조건을 전부 검사하고, 하나라도 어긋나면 FAIL 을 띄운다.

### 리허설 결과 (2026-09-09, 32/32 통과) — **API 기준이다**

무대 7단계를 API 로 실제로 눌러 확인했다.

> ⚠️ 이 결과는 스크립트가 `categoryId` 를 직접 지정해 얻은 것이다. **화면에서 타이핑하는 경로는
> 여기서 검증되지 않는다.** 실제로 `축의금` 이라고 치면 다른 카테고리로 분류돼 GREEN 이 난다
> (위 🚨 절 참조). 브라우저 확인은 아래 "화면 리허설" 을 볼 것.

- 축의금 20만원 → **RED (z = 2.263)** + **"기록의 시작" 칭호** 동시 획득
- 실제 생성된 Gemini 질문(PR #23 중립화 **전**) — *"평소보다 축의금을 넉넉히 내셨는데, 혹시 정말 소중한 분의 특별한 경사가 있으셨나요?"*
- "경조사였다" 답변 → **RED → GREEN**, 코인 **+100**, 펫 스탯 **+10**
- 상점에서 **스터디 테마 잠금 풀림** (1번 칭호의 결과)
- 스터디 가구 2종 배치 → **세트 발동 2/2** (우드는 2/3 로 미발동)
- 분양가 **스탯 740 × 10 × 1.245 = 9,213 코인** (개별 9.50% + 스터디 세트 15.00%)
- **"첫 분양" 획득** → 알 개봉 성공(분양 후라서 가능)

### 화면 리허설 (2026-09-16, 브라우저에서 직접 타이핑)

무대 1·2번을 사람이 하는 그대로 — 로그인해서 폼에 치고 버튼을 눌러 — 확인했다.

```
결혼식 축의금 200,000 입력   → 카테고리 자동분류 '식비·외식'
저장                        → RED  z = 2.263  + '기록의 시작' 칭호 획득
AI 질문 생성                → "평소보다 축의금에 마음을 조금 더 담으셨는데,
                              혹시 정말 가깝고 특별한 분의 결혼식이었나요?"
"친구 결혼식 축의금이라…" 답변 → RED → GREEN · 코인 +100 · 펫 스탯 +10
```

여기서 두 가지가 드러났다.

1. **`축의금` 이라고만 치면 실패한다** — 위 🚨 절. 화면으로 해봐야만 나오는 문제다.
2. **질문 문구가 아직 중립적이지 않다** — *"마음을 조금 더 담으셨는데"*, *"정말 가깝고 특별한 분의"* 는
   묻기도 전에 좋은 지출로 단정한다. 프롬프트 중립화는 PR #23 에 있고, **머지돼야 무대에 반영된다.**
   → PR #23 머지 후 9/17 리허설에서 중립 문구로 나온 것을 확인했다(아래).

### 화면 리허설 (2026-09-17, 최신 main)

PR #25(가구 상점·마이룸) 머지 직후, 새로 세팅한 계정으로 **각본 1·4·5·6·7번**을 화면에서 눌렀다.
2번(답변)은 한도가 새로 찬 16시 이후 **다른 새 계정으로 1·2번만** 다시 눌렀다(아래 두 번째 블록).
3번(칭호 화면)은 이미 확인된 화면이라 이번에는 누르지 않았다.

```
1  결혼식 축의금 200,000 저장  → 식비·외식 분류 · '기록의 시작' 획득
                               저장하자마자 질문 자동 생성(1건 소모):
                               "이번 결혼식 축의금은 평소보다 지출이 컸는데,
                                어떤 일이었는지 가볍게 메모해 줄래?"
4  상점                       → 코르크 보드·컴퓨터의 🔒 가 사라지고 구매 가능
5  두 개 구매                  → 코인 63,537 → 48,537 (정확히 −15,000)
   마이룸에서 배치              → 서버 기준 스터디 2/2 발동 · 우드 2/3 미발동
6  분양                       → 9,088 코인 = 스탯 730 × 10 × 1.245 · '첫 분양' 획득
7  기본 알 구매 → 개봉          → 결과 카드가 바로 뜸 (판다 C등급)
```

```
[16:21 새 계정]
1  결혼식 축의금 200,000 저장  → 가계부 표 '비합리적' · 홈 최근 업적 '기록의 시작 완료'
                               질문: 위와 같은 문구 (Gemini 1건)
2  "친구 결혼식 축의금이라 안 낼 수가 없었어요" 답변
                            → 표 '합리적' · 코인 63,537 → 63,637 · 스탯 730 → 740 (Gemini 1건)
```

조작 순서와 각 결과가 **어느 화면에 보이는지**는 1장 "1·2번 화면 조작 순서" 에 정리했다.

여기서 드러난 것.

1. **세트가 발동해도 화면에 표시가 없었다** — PR #27 로 방 카드에 세트 칩을 붙였다.
   분양 버튼도 보너스 없는 값 *"분양하기 (7,300 코인~)"* 을 보여준다.
2. **컴퓨터가 펫에 가려진다** — 1장 "5번 — 배치하고 나면 컴퓨터를 펫 옆으로 옮길 것".
3. **칭호를 따도 팝업 알림은 없다** — 다만 [완료하기] 뒤 도착하는 **홈의 "최근 업적"** 에 '기록의 시작 — 완료' 가 바로 보인다. 1번에서 그걸 짚는다.
   (처음에는 "3번 칭호 화면에서 처음 보인다" 고 적었으나, 2차 확인에서 홈에 뜨는 것을 봤다.)
6. **판정·보상이 입력 화면에 뜨지 않는다** — RED/GREEN 은 가계부 표의 배지, 코인은 상점, 스탯은 마이룸에서만 보인다.
4. **알 개봉에 연출이 없다** — 누르면 결과 카드가 바로 나온다. 각본 문구를 그렇게 고쳤다.
5. **RED 지출은 저장만 해도 `generateContent` 1건을 쓴다** — 답변하지 않아도 질문이 생성된다. 5장 한도 절 참조.

## 5. 리허설 체크리스트

발표 3일 전(9/27)까지 한 번은 처음부터 끝까지 돌려볼 것.

- [ ] **연동 우선순위 1~4 가 끝났는지 먼저 확인** — 안 끝났으면 각본 3·4번을 무대에서 보여줄 수 없다 (3장 참조)
- [ ] `python scripts/demo_seed.py --rehearse` 로 API 단 각본이 성립하는지 확인
- [ ] `python scripts/demo_seed.py` 로 발표용 계정을 새로 만들고, **화면에서** 1~7번을 눌러보기
- [ ] 전체 소요 시간 측정 (목표 3분 이내, 설명 포함 5분)
- [ ] 영수증 병렬 업로드 타이밍 맞춰보기
- [ ] 발표용 노트북에서 확인 (다른 기기에서 되던 게 안 될 수 있다)

API 단 리허설은 스크립트가 대신해준다. 사람이 확인해야 하는 건 **화면에서 실제로 그렇게 보이는지**다.

### 사고 대비

| 상황 | 대비 |
|---|---|
| **Gemini 429 (하루 20건 소진)** | **발표 전날 오후 4시부터 AI 를 부르는 동작 금지.** 아래 참조 |
| **IPv6 만 잡히는 네트워크** | `build.gradle` 에 `-Djava.net.preferIPv4Stack=true` 를 박아뒀다 |
| AI 판정 버튼이 안 눌림 | `.env.local` 의 `REACT_APP_AI_ACTIVE_FROM_HOUR=0` 을 확인 |
| 인터넷/서버 문제 | 각 단계 화면 캡처를 미리 떠둔다 |
| 영수증이 실패하거나 느림 | 결과 화면 캡처를 준비. 넘어가고 나중에 언급 |
| 가챠에서 C등급만 나옴 | 확률이라 어쩔 수 없다. 등급표를 같이 보여주며 설명 |
| 시연 계정이 망가짐 | **예비 계정을 하나 더 세팅해 둔다** |

### 🔴 Gemini 무료 한도가 생각보다 훨씬 낮다 — 가장 큰 시연 위험

2026-09-09 에 429 응답 원문에서 확인한 실측값이다.

```json
"quotaId":    "GenerateRequestsPerDayPerProjectPerModel-FreeTier",
"quotaValue": "20",
"model":      "gemini-3.6-flash",
"retryDelay": "33s"
```

**`generateContent` 무료 한도가 20건이다.** 블로그 요약에 흔히 나오는 "1,500 requests/day" 와 다르다 — 모델·메트릭마다 별도 쿼터가 걸린다. 실측을 믿을 것.

**시연 1회가 `generateContent` 2건을 쓴다** (질문 생성 + 답변 분류). 즉 **리허설 10번이면 하루치가 사라진다.**

> ⚠️ 영수증 OCR 도 같은 메트릭을 쓴다. 시연에 영수증을 넣으면 회당 3건이다.
> 임베딩(`gemini-embedding-001`)은 다른 모델이라 별도 쿼터다 — 서버 재시작은 이 한도와 무관하다.

### 한도는 자정이 아니라 **오후 4시**에 찬다

> "Requests per day (RPD) quotas reset at midnight Pacific time." — [Gemini API Rate limits 문서](https://ai.google.dev/gemini-api/docs/rate-limits)

태평양 자정은 **한국 시각 오후 4시**다(미국 서머타임 기간 기준). 실측에서도 16시 무렵에 풀렸다.
그래서 한도의 "하루" 는 이렇게 끊긴다.

```
9/29(화) 16:00 ──────────────── 9/30(수) 16:00
         ↑ 여기서부터 쓰는 호출은 전부 발표 몫에서 빠진다
```

**발표가 9/30 오후 4시 전이면, 9/29 오후 4시 이후의 리허설은 본 발표 한도를 갉아먹는다.**
"전날 저녁에 마지막으로 한 번" 이 가장 위험하다.

> 11/4 최종발표는 서머타임이 끝난 뒤(11/1)라 경계가 **11/3 오후 5시**다.

#### 한도를 쓰는 동작 · 안 쓰는 동작

| 한도를 쓴다 (`generateContent`) | 안 쓴다 |
|---|---|
| **큰 지출 저장** — RED 면 질문이 **저장하자마자 자동 생성**된다. 답변을 안 해도 1건 | 칭호 화면 · 상점 · 가구 구매·배치 |
| 답변 제출 (사유 분류) | 펫 분양 · 알 구매·개봉 |
| 영수증 업로드 | 지출 카테고리 자동분류 (임베딩 — 별도 쿼터) |
| 일일 리포트 생성 (00:10 자동 · `POST /api/daily-reports/generate`) | 로그인 · 화면 이동 |

→ 전날 오후 4시 이후에도 **각본 3~7번은 연습해도 된다.** 1·2번과 영수증만 막는다.

#### 밤 00:10 배치도 같은 한도를 쓴다

일일 리포트 스케줄러가 매일 00:10 에 **전날 지출·수입이 있는 계정마다 1건**씩 AI 를 부른다.
9/29 에 리허설 계정을 3개 만들고 백엔드를 켜둔 채 자면, 9/30 00:10 에 3건이 발표 몫에서 빠진다.

**발표용 노트북의 백엔드는 9/29 밤에 끄고 잔다.** 00:10 에 꺼져 있으면 배치는 돌지 않고,
다음에 켜도 밀린 것을 몰아서 실행하지 않는다.

**대응**

| | 방법 | 비고 |
|---|---|---|
| 1 | **발표 전날 오후 4시부터 1·2번·영수증 리허설 금지** | 3~7번은 괜찮다. 위 표 참조 |
| 2 | **1·2번 장면 화면 녹화를 미리 떠둔다** | 429 가 나면 녹화로 대체한다. 가장 확실한 보험 |
| 3 | 전날 밤 발표용 백엔드를 끈다 | 00:10 배치가 발표 몫을 쓰지 않게 |
| 4 | 시연 직전 남은 횟수를 확인한다 | https://ai.dev/rate-limit |
| 5 | 리허설과 본 발표의 **Google 프로젝트**를 나눈다 | 한도는 **키가 아니라 프로젝트 단위**다. 같은 프로젝트에서 키를 새로 만들어도 한도는 하나다. 팀원이 각자 노트북에서 돌려도 `.env` 의 키가 같으면 같은 20건에서 빠진다 |

**1·2·3번을 함께 한다.** 운영으로 막고, 그래도 터지면 녹화로 넘어간다.

> ⚠️ 1학기 회의록의 학과 지원 항목 'AI 구독 요금 3개월' 은 **코딩용 AI 구독**이지
> Gemini API 크레딧이 아니다. 이 문제에는 쓸 수 없다.
> 유료 티어로 올리려면 Google AI Studio 에 결제 수단을 연결해야 하는데, 학부 작품에
> 개인 카드를 거는 건 권하지 않는다.
