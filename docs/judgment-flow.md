# 하루 판정 흐름 — 신호등 판정 · 예외 지출 판정 · 자정 보상

> 작성 2026-10-07 · 갱신 2026-10-08 · 상태: **구현됨** (`jonghdch` 브랜치, main 머지 전) · 구현 담당: 정다은
>
> 하루 판정이 어떤 단계로 흘러가는지, 각 단계에서 무엇을 하고 **어떤 조건에서 다음 단계로 넘어가는지**를 정리한다.
> [`roadmap.md`](roadmap.md) 7절 「알려진 문제」 1·3·8번이 이 흐름으로 해결됐다.
> 숫자·규칙은 코드 기준이다. 코드와 다르면 코드(`DailyJudgmentService`·`JudgmentRewardSettler`·`WalletAnalysisPage`)를 우선하고 이 문서를 고친다.

## 1. 판정은 두 가지다

| 판정 | 무엇을 보나 | 언제 |
|---|---|---|
| **신호등 판정** | 스탯 그룹(식비·쇼핑뷰티·문화여가·생활고정비)마다 오늘 쓴 돈을 하루 예산(봉투)과 비교해 초록·노랑·빨강을 정한다. 하루 신호는 네 그룹 중 가장 주의가 필요한 색 | 「판정하기」를 누르면 **1차**, 예외 지출 판정이 끝나면 **최종** |
| **예외 지출 판정** | 평소보다 크게 쓴 빨간 지출(예외 지출)마다 사유를 묻고, 사유에 따라 그 지출의 신호등을 바꾼다 | 1차 신호등 판정 바로 뒤 |

**보상(코인·스탯)은 최종 신호등 판정에 따라 정해지고 그날 자정에 무조건 한 번 지급된다.**
판정을 받은 뒤에는 지출을 고쳐도 보상이 바뀌지 않는다.

> 지출 하나하나에 붙는 신호(가계부에 입력할 때 평소 금액과 비교해 붙는 색)는 예외 지출을 골라내는 기준이다.
> 처음 붙은 신호가 빨강인 지출(반복 결제 제외)에 AI 질문이 생기고, 이것이 예외 지출 판정의 대상이다.

## 2. 한눈에 보기

```
 지출 입력 ──▶ 지출마다 신호(빨강이면 AI 질문 생성)
                    │
 오후 8시 ──────────┼──────────────────────────────────────────────────────────────
                    ▼
 [판정하기] ──▶ ① 1차 신호등 판정 ──예외 지출 없음──────────────────▶ ③ 최종 신호등 판정
                    │                                                        ▲
                    └──예외 지출 있음──▶ ② 예외 지출 판정(사유 입력) ──「완료」/「건너뛰기」┘
                                              │
                                        「돌아가기」(그대로 둠, 그날 다시 들어오면 ②부터)

 자정 ──────────────────────────────────────────────────────────────────────────────
   ④ 자정 정산: ②에서 멈춘 날 → 1차 신호등 판정으로 확정 / 판정하지 않은 날 → 신호등 판정을 대신 내림
               → 최종 신호등 판정 기준으로 보상 지급(한 번)
```

판정 행(`daily_judgments`)의 상태:

| 상태 | 뜻 | 보상 |
|---|---|---|
| (행 없음) | 아직 판정하지 않음 | — |
| `PENDING` | ① 1차 신호등 판정만 끝남. 예외 지출 사유를 기다리는 중 | 미지급. 보상 칸은 1차 판정 기준 값 |
| `FINALIZED` | ③ 최종 신호등 판정이 남 | 그날 자정에 지급(`rewarded_at` 기록). 그전까지는 "자정에 받을" 값 |

```
(행 없음) ──①──▶ PENDING ──③ 사유 입력 끝/건너뛰기──▶ FINALIZED ──④ 자정──▶ 보상 지급
    │               └──④ 자정(1차 판정 그대로)──────▶ FINALIZED ──④──▶ 보상 지급
    ├──①(예외 지출 없음, 같은 요청에서 ③까지)──────────▶ FINALIZED ──④──▶ 보상 지급
    └──④ 자정(판정하지 않은 날, 지출이 있을 때만)────────▶ FINALIZED ──④──▶ 보상 지급
```

## 3. 단계별 진행 조건

### ⓪ 소비 판정 화면 진입 (`/wallet/analysis`)

| | |
|---|---|
| 들어오는 조건 | 일반 계정: **오늘, 오후 8시 이후**(서버 `vori.ai-judge.open-hour`·화면 `AI_ACTIVE_FROM_HOUR`, 기본 20). 시간 밖이면 가계부로 돌려보낸다. 관리자: 시각 제한 없고 `?date=` 로 지난 날짜도 연다 |
| 알림 | 오후 8시에 그날 지출을 적었고 아직 판정하지 않은 사용자에게 「오늘 소비를 판정할 수 있어요」 |
| 하는 일 | 화면에 들어온 순간의 날짜를 고정한다(자정을 넘겨도 다른 날짜로 요청하지 않게). 그날 판정 행이 있는지 조회한다 |
| 다음 단계 | 행이 **없으면** 확인 창(「하루에 한 번 판정할 수 있습니다」) → 「판정하기」를 눌러야 ① / 「돌아가기」면 가계부로 |
| | 행이 **있으면** 확인 창 없이 ①의 요청을 다시 보낸다 — 서버는 다시 계산하지 않고 저장된 단계를 돌려준다 |

### ① 1차 신호등 판정 — `POST /api/daily-judgments?date=` (또는 `/today`)

| | |
|---|---|
| 요청 조건 | 일반 계정은 날짜가 오늘이고 오후 8시 이후여야 한다(아니면 403). 관리자는 제한 없음 |
| 하는 일 | 그룹마다 봉투와 오늘 지출을 비교해 신호등을 정한다(4절). `PENDING` 으로 저장하고 같은 값을 1차 결과 칸(`initial_signal`·`initial_group_details`)에도 남긴다 |
| 다음 단계 | 그날 **답하지 않은 AI 질문(예외 지출)이 0건**이면 같은 요청 안에서 ③까지 → 응답 `status=FINALIZED` |
| | 1건 이상이면 `status=PENDING` → 화면은 ② |
| 이미 행이 있을 때 | `PENDING` → 저장된 1차 결과 그대로 → 화면은 ②로 이어서 |
| | `FINALIZED` → 저장된 최종 결과(`alreadyJudged=true`) → 화면은 결과. 질문이 남아 있어도 보여 주지 않는다 |
| | 관리자가 `FINALIZED` 인 날을 다시 판정하면 신호·그룹 결과를 다시 계산한다. 보상을 이미 지급한 날이면 보상 칸은 그대로 둔다 |

화면은 빨간 지출인데 질문이 아직 안 보이면 2초 간격으로 두 번까지 다시 조회한다.

### ② 예외 지출 판정 (사유 입력)

| | |
|---|---|
| 들어오는 조건 | ①의 응답이 `PENDING` 이고 답할 질문이 1건 이상 |
| 화면 | 예외 지출을 한 건씩 넘겨 보며 사유 칩(경조사·갑작스러운 일·모임·만남·배움·자기계발·사고 싶어서·기타)을 고르거나 글을 쓴다. 위에 「1차 판정은 ○○이에요. 사유를 답하거나 건너뛰면 최종 판정이 나고, 보상은 오늘 자정에 들어와요」 |
| 버튼과 다음 단계 | **「완료」** → 칩이나 글이 있는 질문만 답변을 보내고(`POST /api/inquiries/{id}/answer`) 이어서 ③. 답하지 않은 예외 지출은 빨강 그대로 |
| | **「건너뛰고 판정 받기」** → 답변 없이 바로 ③ — 1차 신호등 판정 그대로 최종이 된다(D4) |
| | **「돌아가기」** → 그대로 두고 가계부로. `PENDING` 으로 남고, 그날 다시 들어오면 확인 창 없이 ②부터 이어서 |
| | 질문을 다시 불렀는데 0건이면(다른 화면에서 이미 답함) 바로 ③ |

사유가 예외 지출의 신호등을 바꾸는 방식(`AiInquiryService`):

| 사유 | 그 지출의 신호등 |
|---|---|
| 경조사(`CEREMONY`)·갑작스러운 일(`EMERGENCY`)·배움·자기계발(`SELF_INVEST`) | 초록 |
| 모임·만남(`SOCIAL`) | 노랑 |
| 사고 싶어서(`IMPULSE`)·기타(`ETC`) | 빨강 그대로 |

- 칩을 고르면 그 사유를 그대로 쓴다(AI 호출 없음). 글만 쓰면 AI 가 사유를 분류하고, AI 가 실패하면 낱말 규칙으로, 그래도 모르면 기타.
- 신호등이 바뀐 예외 지출에는 `signal_adjusted=TRUE` 가 남는다 — ③에서 "인정된 예외 지출"을 가리는 기준이다.

### ③ 최종 신호등 판정 — `POST /api/daily-judgments/finalize?date=`

| | |
|---|---|
| 요청 조건 | 일반 계정은 날짜가 **오늘**이어야 한다(아니면 403 — 자정이 지난 날은 ④가 처리한다). 그날 판정 행이 없으면 409 「먼저 판정을 받아 주세요」 |
| 이미 `FINALIZED` | 저장된 결과를 그대로 돌려준다(`alreadyJudged=true`) |
| 하는 일 | ①과 같은 계산을 다시 하되, **인정된 예외 지출**(처음엔 빨강이었고 사유로 신호등이 바뀐 지출)이 있는 그룹은 빨강을 그 지출의 바뀐 신호등까지 완화한다(4절). 최종 결과와 **보상(자정에 지급할 값)**을 저장하고 `FINALIZED` 로 바꾼다 |
| 보상 | 여기서 주지 않는다. 그날 자정(④)에 저장된 값 그대로 준다 — 이후 지출을 고쳐도 바뀌지 않는다. 단, 관리자가 지난 날짜를 판정한 경우는 그 날 자정이 이미 지났으므로 바로 준다 |
| 다음 단계 | 결과 화면 — 하루 신호·그룹별 판정·「자정에 받을 코인」. 1차보다 순해진 그룹에만 「1차 판정은 빨강 · 과소비였지만 예외 지출 사유가 인정돼 초록 · 합리적으로 바꿨어요」 |

### ④ 자정 정산 — `JudgmentRewardSettler`

| | |
|---|---|
| 언제 | 매일 00:00(한국 시간). 자정에 서버가 꺼져 있었던 경우에 대비해 서버가 뜰 때도 한 번 돈다 |
| 1. 사유 입력을 끝내지 않은 날 | 지난 날짜의 `PENDING` → 예외 지출 판정 없이 **1차 신호등 판정 그대로** `FINALIZED`(D7). 다시 계산하지 않고 ①에서 저장한 결과·보상을 쓴다 |
| 2. 판정하지 않은 날 | 어제 지출을 하나 이상 적었는데 판정 행이 없는 사용자 → 신호등 판정을 대신 내려 `FINALIZED`(사유 반영 없음). 지출이 없는 날은 판정하지 않는다(안 쓴 날로 계산돼 최대 보상이 나가지 않게). 어제 하루만 본다 |
| 3. 보상 지급 | `FINALIZED` 인데 아직 지급하지 않은 지난 날짜 판정 → 저장된 보상(코인·스탯)을 지급하고 `rewarded_at` 기록 |
| 중복·동시 요청 | 사용자 행을 잠근 뒤 다시 읽어 아직 지급 전일 때만 지급한다 — 정산이 두 번 돌아도 한 번 |
| 실패 | 한 건이 실패해도 나머지는 계속 처리하고 ERROR 로그를 남긴다. 그 건은 다음 실행(다음 자정·서버 재시작) 때 다시 처리된다 |

## 4. 신호등과 보상 계산 (①·③·④ 공통)

스탯 그룹마다:

1. **하루 봉투** — 월 예산을 날짜 수로 나눈 몫에 전날 남긴 금액의 절반을 더하고 전날 초과한 금액은 전부 뺀다.
2. **신호등** — 오늘 그 그룹 지출 합계가 봉투의 85% 이하면 초록, 봉투 이하면 노랑, 넘으면 빨강. 월 예산을 이미 다 써서 오늘 봉투가 0원이고 지출도 없으면 노랑(예산 소진).
3. **예외 지출 반영(③만)** — 신호등이 빨강이고 그 그룹에 인정된 예외 지출이 있으면 그 지출들의 신호등 중 가장 순한 것으로 바꾼다. 처음부터 빨강이 아니던 평범한 지출은 근거가 아니다.
4. **보상** — 남긴 금액(봉투 − 지출, 0 이상) 1,000원마다 그 스탯 +1(그룹당 최대 15). 코인은 네 그룹 남긴 금액 합계의 1/100. 배치한 가구의 배웅 보너스가 붙고 펫 스탯은 100 상한.

> **예외 지출 반영은 신호등만 바꾸고 보상은 바꾸지 않는다.** 예산을 넘긴 그룹은 남긴 금액이 0원이라 사유가 인정돼도 그 그룹 보상은 0이다.
> 인정된 금액만큼 보상도 늘리려면 Q1 (나)가 필요하다(6절).

## 5. 판정 밖에서 일어나는 일

| 상황 | 동작 |
|---|---|
| 지출 수정 — 내역 이름·결제수단만 바꿈 | 그 지출의 신호와 AI 질문·답변이 그대로 남는다(D6) |
| 지출 수정 — 금액이나 카테고리를 바꿈 | 그 지출의 신호를 다시 매기고, 빨강이면 AI 질문을 새로 만든다 |
| 판정(①·③) 뒤 그날 지출 추가·수정·삭제 | 하루 판정과 보상은 바뀌지 않는다. `PENDING` 이면 ③에서 다시 계산할 때 반영된다 |
| 가계부 달력·보상 칸 | `FINALIZED` 만 판정 색. 보상은 지급 전이면 「자정에 받을 코인」, 지급 후 「받은 코인」. `PENDING` 이면 오늘은 「사유 답변 대기」, 지난 날은 ④ 직전 잠깐 「1차 판정으로 확정 중」 |
| 월간 리포트 | `FINALIZED` 인 날만 센다 |

## 6. 결정 사항

### 사용자 결정 (정다은, 2026-10-07 ~ 10-08)

| # | 결정 | 근거 발화 |
|---|---|---|
| D1 | 판정은 **신호등 판정**과 **예외 지출 판정** 두 가지다. 「판정하기」를 누르면 1차로 신호등 판정, 2차로 예외 지출을 잡아 사유를 묻고, 사유에 따라 예외 지출의 신호등이 바뀐다 | 「판정이 두가지가 있는데 신호등 판정이랑 예외 지출 판정이 있어 … 1차로 신호등 판정을 내리고 2차로 예외 지출을 잡아내서 사유를 물어보는거야. 사유에 따라서 예외 지출 신호등 판정이 바뀌는거고」 |
| D2 | 이 단계를 모두 거친 **최종 신호등 판정에 따라 보상**을 준다 | 「이 단계를 모두 거치고 나면 그떄서야 최종 신호등 판정에 따라 보상을 줘」 |
| D3 | 사유 입력이 다 끝나면 확정이다. 판정 받기는 하루에 한 번이다 | 「사유 입력이 다 끝나면 확정인거야 판정 받기는 하루에 한 번이니까」 |
| D4 | 건너뛰기를 누르면 1차 판정 그대로 간다 | 「건너뛰기를 누르면 이전 판정대로 그대로 가야지」 |
| D5 | 그날 판정이 끝나면 끝이다 | 「그 날의 판정이 끝나면 끝인거야」 |
| D6 | 지출 수정 시 카테고리나 금액이 바뀌면 다시 판정, 내역 이름만 바뀌면 다시 판정하지 않는다 | 「카테고리 변화가 있는 상태로 저장이 되면 그 때 판정되는걸로」, 「금액이 바뀌면 다시 판정해야지」 |
| D7 | 자정이 지나도록 끝내지 않으면 예외 지출 판정 없이 1차 판정 내용으로 보상 | 「자정이 지나면 예외 지출에 대한 판정 없이 1차 판정 내용으로만 보상을 주는 식으로 가야할 것 같아」 |
| D8 | **보상은 당일 자정에 무조건 지급**. 판정을 받은 뒤에는 수정 사항이 있어도 보상(스탯·코인)이 바뀌지 않는다 | 「보상은 당일 자정에 무조건 지급이고 이전에 판정을 받고 나면 이후 수정 사항이 있어도 보상(스탯, 코인)은 바뀌지 않아」 |
| D9 | 판정은 원래대로 **오후 8시 이후** 「판정하기」로 시작한다 (10-08, 10시 → 8시) | 「오후 8시로 되어있었다고 하는데 8시로 바꿔줄래?」 |
