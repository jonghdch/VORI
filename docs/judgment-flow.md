## 2. 지금 동작 (2026-10-07 main `0aed883` 기준)

```
[판정하기] ─▶ POST /api/daily-judgments  ─▶ 판정 계산 + 보상 지급 + 저장  (끝)
                                           │
[질문 답변] ─▶ POST /api/inquiries/{id}/answer ─▶ 지출 signal_final 만 바뀜
                                           (하루 판정·보상은 그대로)
```

- `WalletAnalysisPage` 가 확인 창의 「판정하기」에서 `startDateJudgment` 로 판정을 요청하고, 질문 목록은 그 **뒤에** 보여 준다.
- `DailyJudgmentService.judgeDate` 는 계산(`evaluate`)과 지급(`grant`)을 한 트랜잭션에서 끝낸다. 일반 사용자는 같은 날 두 번째 요청에 저장된 결과를 돌려받는다.
- `AiInquiryService.answerInquiry` 는 사유로 지출의 `signal_final` 을 바꾸지만 **하루 판정을 건드리지 않는다.**
  그래서 답변 뒤 화면에 「모든 지출이 초록」이 떠도 그날 판정은 빨강으로 남는다(#100 본문 실측).
- 그룹 완화 조건(`evaluate`)은 그 그룹에 **빨강이 아닌 지출이 하나라도** 있으면 빨강을 푼다. AI 인정 여부를 보지 않는다(roadmap 7절 1번).
- 관리자는 같은 날을 다시 판정할 수 있고 그때마다 보상이 다시 지급된다(roadmap 7절 3번).
- 지출 일괄 저장(`LedgerService.updateExpense`)은 내역·금액·카테고리 중 하나라도 바뀌면 `ExpenseService.updateExpense` 로 다시 판정하고 그 지출의 AI 질문·답변을 지운 뒤 새로 만든다(#99).

## 3. 바뀌는 흐름

```
① 1차 판정 ─────────────▶ ② 예외 지출 사유 ─────────▶ ③ 예외 지출 판정·확정
  봉투 계산, 결과 표시        빨강 지출마다 칩/글 답변        인정된 지출 반영해 다시 계산
  보상 없음(「확정 후 지급」)   「다음에 할게요」= 건너뛰기      보상 1회 지급
  status = PENDING           (D4: 1차 결과로 ③)            status = FINALIZED
```

1. **1차 판정** — 「판정하기」를 누르면 지금처럼 봉투로 계산해 결과를 보여 준다. 저장은 하되 **보상은 주지 않는다.**
   - 그날 답할 예외 지출(답변 안 된 AI 질문)이 **없으면** 같은 요청에서 바로 ③으로 가 확정·지급한다.
2. **예외 지출 사유** — 빨강 지출마다 사유 칩이나 글로 답한다(#100 화면 그대로). 답변은 지출의 `signal_final` 을 바꾼다(지금과 같음).
3. **예외 지출 판정·확정** — 사유 입력이 다 끝나면(D3) 그날을 다시 계산하고 1차와 달라진 점을 보여 주며 보상을 **한 번** 지급한다(D2).
   - 「다음에 할게요」(건너뛰기)를 누르면 답하지 않은 지출은 빨강 그대로 두고 같은 방식으로 확정한다. 아무것도 답하지 않았다면 결과는 1차와 같다(D4).
   - 확정한 날은 다시 판정하지 않는다(D3·D5). 확정 뒤 들어온 답변은 지출 신호에만 남고 하루 판정에는 반영하지 않는다.

## 4. 데이터

### `daily_judgments` 에 더할 칸 (마이그레이션 V50 — 번호는 머지 직전 main 기준으로 다시 확인)

| 칸 | 형식 | 뜻 |
|---|---|---|
| `status` | `ENUM('PENDING','FINALIZED') NOT NULL DEFAULT 'FINALIZED'` | ①만 끝난 판정 / 확정된 판정 |
| `initial_signal` | `ENUM` (signal 과 같은 값), NULL 허용 | 1차 판정 신호 |
| `initial_group_details` | `TEXT`, NULL 허용 | 1차 스탯별 결과 JSON (#95 `group_details` 와 같은 형식) |
| `finalized_at` | `DATETIME`, NULL 허용 | 확정 시각 |

- 기존 행은 모두 이미 보상을 받은 판정이므로 `FINALIZED` 로 둔다(기본값으로 채워짐). `initial_*` 는 NULL — 화면은 「1차 기록 없음」.
- 지금 칸(`signal`·`group_details`·`saved_amount`·`coin_reward`·`reward_details`)은 **최종 결과**를 담는다. PENDING 동안에는 1차 결과와 같은 값을 넣어 두고 확정 때 덮어쓴다.
- `coin_reward`·`reward_details` 는 PENDING 동안 "지급 예정" 값이다. 실제 지급 여부는 `status` 로 판단한다.

### 상태 전이

```
(없음) ──판정하기──▶ PENDING ──사유 입력 완료 / 건너뛰기──▶ FINALIZED
   └──판정하기(답할 예외 지출 없음)─────────────────────────▶ FINALIZED
```

## 5. 서버 변경

### `DailyJudgmentService`

- `judgeDate` 를 두 단계로 나눈다.
  - **1차** `judgeDate(userId, role, date)`
    - 행이 없으면: `evaluate` → `PENDING` 으로 저장(보상 없음). 그날 답변 안 된 질문(`AiInquiryService.listPendingByDate`)이 0개면 이어서 `finalize` 를 부른다.
    - 행이 `PENDING` 이면: 저장된 1차 결과를 그대로 돌려준다(다시 계산하지 않음 — Q2 「이어서 답하기」).
    - 행이 `FINALIZED` 면: 지금처럼 저장된 결과를 `alreadyJudged=true` 로 돌려준다.
  - **확정** `finalize(userId, role, date)` (새로 만듦)
    - 사용자 행 잠금(`findByIdForUpdate`) 후 판정 행을 다시 읽어 `PENDING` 일 때만 진행한다 — 연속 클릭·재시도에 보상이 두 번 나가지 않게.
    - `evaluate` 를 다시 돌려 최종 결과를 만들고, `grant` 로 **한 번** 지급, `FINALIZED`·`finalized_at` 기록.
- **완화 조건 고치기(roadmap 7절 1번)** — 그룹 빨강을 푸는 지출을 "`signal_initial` 이 빨강이었고 AI 답변으로 신호가 바뀐(`ai_inquiries.signal_adjusted = TRUE`) 지출" 로 좁힌다.
  완화 정도는 Q1 결정에 따른다.
- **관리자 재판정(roadmap 7절 3번)** — 관리자가 이미 확정된 날을 다시 판정하면 결과만 다시 계산해 보여 주고 **보상은 다시 주지 않는다**(제안). 시연용 지난 날짜 판정은 행이 없는 날에만 보상이 나간다.

### `AiInquiryService`

- 바꾸지 않는다. 답변은 지금처럼 지출 `signal_final` 만 바꾸고 하루 판정 반영은 `finalize` 가 다시 계산할 때 일어난다.
- 확정된 날의 질문에 답하는 경우(Q4)도 지금처럼 저장만 한다.

### `LedgerService` (D6)

- `sameJudgedFields` 에서 **내역 비교를 뺀다** — 금액·카테고리가 같으면 다시 판정하지 않는다.
- 내역만 바뀌면 지출의 내역만 고치고(`Expense` 에 내역만 바꾸는 메서드 필요) AI 질문·답변은 그대로 둔다. 질문 문구에는 예전 이름이 남는다 — 그때 그 이름으로 물은 기록이다.
- 금액이나 카테고리가 바뀌면 지금처럼 `ExpenseService.updateExpense` 로 다시 판정한다(질문·답변 새로 만듦).

### API

| 요청 | 지금 | 바뀐 뒤 |
|---|---|---|
| `POST /api/daily-judgments` · `/today` | 판정 + 지급 + 저장 | 1차 판정 저장. 예외 지출이 없으면 확정까지 |
| `POST /api/daily-judgments/finalize?date=` | 없음 | **새로 만듦.** 확정·지급. 「완료」와 「다음에 할게요」 모두 이걸 부른다 |
| `GET /api/daily-judgments/today` · `?date=` · `/month` | 저장된 결과 | 응답에 `status`·`initialSignal`·`initialGroupJudgments` 추가 |

`DailyJudgmentResponse` 에 더할 것: `status`, `initialSignal`, `initialGroupJudgments`, `pendingInquiryCount`.

## 6. 화면 변경 (`WalletAnalysisPage`)

1. 확인 창 「판정하기」 → 1차 결과 표시. 보상 칸은 「사유를 답하면 확정돼요」로, 숫자 대신 예정 값을 흐리게.
2. 그 아래 질문 목록(#100 칩 + 글). 「완료」를 누르면 답변을 모두 보낸 뒤 `finalize` 를 부른다.
3. 「다음에 할게요」 → 답변 없이 `finalize`(D4).
4. 확정 결과 화면 — 1차와 최종을 나란히: 「식비 빨강 → 초록 (경조사 인정)」, 지급된 코인·스탯.
5. 그날 다시 들어왔을 때 `status=PENDING` 이면 질문 단계부터 이어서 보여 준다(Q2 제안).
6. 가계부 달력(`WalletPage`)은 `FINALIZED` 만 판정 색을 칠하고, `PENDING` 은 「답변 대기」로 표시.

## 7. 테스트 (구현 때)

- 예외 지출이 있으면 1차 판정은 `PENDING` 이고 코인·스탯이 그대로다

- 카테고리만 바꾸면 다시 판정한다
