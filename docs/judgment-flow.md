# 하루 판정 흐름 — 1차 판정 → 예외 지출 사유 → 확정

> 작성 2026-10-07 · 갱신 2026-10-08 · 상태: **구현됨** (`jonghdch` 브랜치, main 머지 전) · 구현 담당: 정다은
>
> 하루 판정이 어떤 단계로 흘러가는지, 각 단계에서 무엇을 하고 **어떤 조건에서 다음 단계로 넘어가는지**를 정리한다.
> [`roadmap.md`](roadmap.md) 7절 「알려진 문제」 1·3·8번이 이 흐름으로 해결됐다.
> 숫자·규칙은 코드 기준이다. 코드와 다르면 코드(`DailyJudgmentService`·`WalletAnalysisPage`)를 우선하고 이 문서를 고친다.

## 1. 한눈에 보기

```
            ┌──────────── 그날 판정 행 없음 ────────────┐
            │                                            ▼
[소비 판정 화면 진입] ──판정 행 있음──▶ (저장된 단계로 이어서)   [확인 창] ──「판정하기」──▶ ① 1차 판정
                                                                                              │
                                    ┌── 답할 예외 지출 0건 ───────────────────────────────────┤
                                    │                                                         │ 답할 예외 지출 1건 이상
                                    ▼                                                         ▼
                              ③ 확정·보상 지급  ◀──「완료」/「건너뛰고 판정 받기」──  ② 예외 지출 사유 입력
                                    │                                                         │
                                    ▼                                                「돌아가기」(확정 안 함)
                              ④ 결과 화면                                                     ▼
                                                                                   PENDING 으로 남음
                                                                          (그날 다시 들어오면 ②부터, 자정이 지나면 ⑤)
```

판정 행(`daily_judgments`)의 상태는 두 가지뿐이다.

| 상태 | 뜻 | 보상 |
|---|---|---|
| (행 없음) | 아직 판정하지 않음 | — |
| `PENDING` | ① 1차 판정만 끝남. 예외 지출 사유를 기다리는 중 | **아직 안 줌**. 행의 보상 칸은 "확정 때 줄 예정" 값 |
| `FINALIZED` | ③ 확정됨 | **지급 완료**(한 번만) |

```
(행 없음) ──① 1차 판정──▶ PENDING ──③ 확정──▶ FINALIZED
                            └──⑤ 자정 자동 확정(1차 판정 내용 그대로)──▶ FINALIZED
    └──① 1차 판정(답할 예외 지출 0건이면 같은 요청에서 ③까지)──▶ FINALIZED
```

## 2. 단계별 진행 조건

### ⓪ 소비 판정 화면 진입 (`/wallet/analysis`)

| | |
|---|---|
| 들어오는 조건 | 일반 계정: **오늘**, 오후 8시(`vori.ai-judge.open-hour`, 기본 20) 이후. 시간 밖이면 가계부로 돌려보낸다. 관리자: 시각 제한 없고 `?date=` 로 지난 날짜도 연다 |
| 하는 일 | 화면에 들어온 순간의 날짜를 고정한다(자정을 넘겨도 다른 날짜로 요청하지 않게). 그날 판정 행이 있는지 조회한다 |
| 다음 단계 | 행이 **없으면** 확인 창(「하루에 한 번 판정할 수 있습니다」) → 「판정하기」를 눌러야 ① / 「돌아가기」면 가계부로 |
| | 행이 **있으면** 확인 창 없이 ①의 요청을 다시 보낸다 — 서버가 다시 계산하지 않고 저장된 단계를 돌려준다(아래 ① "이미 행이 있을 때") |

### ① 1차 판정 — `POST /api/daily-judgments?date=` (또는 `/today`)

| | |
|---|---|
| 요청 조건 | 일반 계정은 날짜가 오늘이고 오후 8시 이후여야 한다(아니면 403). 관리자는 제한 없음 |
| 하는 일 | 스탯 그룹(식비·쇼핑뷰티·문화여가·생활고정비)마다 하루 봉투와 오늘 지출을 비교해 신호를 정한다(3절). 결과를 `PENDING` 으로 저장하고 같은 값을 1차 결과 칸(`initial_signal`·`initial_group_details`)에도 남긴다. **보상은 주지 않는다** |
| 다음 단계 | 그날 **답하지 않은 AI 질문이 0건**이면 같은 요청 안에서 바로 ③ 확정까지 간다 → 응답 `status=FINALIZED` |
| | 1건 이상이면 `status=PENDING` 으로 응답 → 화면은 ② |
| 이미 행이 있을 때 | `PENDING` → 저장된 1차 결과를 그대로 돌려준다(다시 계산 안 함) → 화면은 ②로 이어서 |
| | `FINALIZED` → 저장된 최종 결과(`alreadyJudged=true`) → 화면은 ④. 질문이 남아 있어도 보여 주지 않는다 |
| | 관리자가 `FINALIZED` 인 날을 다시 판정하면 신호·스탯별 결과만 다시 계산해 갱신한다. 보상은 다시 주지 않고 보상 칸(코인·스탯·절약액)은 실제로 지급한 값을 그대로 둔다 |

"답할 AI 질문"은 지출 저장과 함께 만들어지는 질문으로, 그날 지출 중 처음 판정이 빨강이었던 것(반복 결제 제외)이 대상이다.
화면은 빨강 지출인데 질문이 아직 안 보이면 2초 간격으로 두 번까지 다시 조회한다.

### ② 예외 지출 사유 입력

| | |
|---|---|
| 들어오는 조건 | ①의 응답이 `PENDING` 이고 답할 질문이 1건 이상 |
| 화면 | 질문을 한 건씩 넘겨 보며 사유 칩(경조사·갑작스러운 일·모임·만남·배움·자기계발·사고 싶어서·기타)을 고르거나 글을 쓴다. 위에 「1차 판정은 ○○이에요. 사유를 답하거나 건너뛰면 판정이 확정되고 보상이 들어와요」 |
| 버튼과 다음 단계 | **「완료」** → 칩이나 글이 있는 질문만 답변을 보내고(`POST /api/inquiries/{id}/answer`) 이어서 ③. 답하지 않은 질문은 그대로 둔다 |
| | **「건너뛰고 판정 받기」** → 답변을 보내지 않고 바로 ③ — 1차 판정 그대로 확정된다(D4) |
| | **「돌아가기」** → 확정하지 않고 가계부로. 판정은 `PENDING` 으로 남고 그날 다시 들어오면 확인 창 없이 ②부터 이어서 |
| | 화면이 질문을 다시 불렀는데 0건이면(다른 화면에서 이미 답함) 기다릴 것이 없으므로 바로 ③ |

답변 한 건이 처리되는 방식(`AiInquiryService.answerInquiry`):

| 사유 | 그 지출의 최종 신호(`signal_final`) |
|---|---|
| 경조사(`CEREMONY`)·갑작스러운 일(`EMERGENCY`)·배움·자기계발(`SELF_INVEST`) | 초록 |
| 모임·만남(`SOCIAL`) | 노랑(회색) |
| 사고 싶어서(`IMPULSE`)·기타(`ETC`) | 처음 신호 그대로(빨강) |

- 칩을 고르면 그 사유를 그대로 쓴다(AI 호출 없음). 글만 쓰면 AI 가 사유를 분류하고 AI 가 실패하면 낱말 규칙, 그래도 모르면 기타.
- 신호가 바뀌었으면 질문에 `signal_adjusted=TRUE` 가 남는다 — ③에서 "인정된 예외 지출"을 가리는 기준이다.
- 답변은 지출 신호만 바꾼다. 하루 판정은 ③에서 다시 계산할 때 반영된다.

### ③ 확정·보상 지급 — `POST /api/daily-judgments/finalize?date=`

| | |
|---|---|
| 요청 조건 | 일반 계정은 날짜가 **오늘**이어야 한다(아니면 403 — 자정이 지난 날은 ⑤가 확정한다, D7). 그날 판정 행이 없으면 409 「먼저 판정을 받아 주세요」 |
| 이미 `FINALIZED` | 저장된 결과를 그대로 돌려준다(`alreadyJudged=true`). 보상은 다시 주지 않는다 — 연속 클릭·재시도에도 한 번 |
| 하는 일 | ①과 같은 계산을 다시 하되, **인정된 예외 지출**(처음엔 빨강이었고 답변으로 `signal_adjusted=TRUE` 가 된 지출)이 있는 그룹은 빨강을 그 지출의 낮아진 신호까지 완화한다(3절). 최종 결과를 저장하고 `FINALIZED`·`finalized_at` 을 기록한 뒤 **보상을 한 번 지급**한다(D2) |
| 동시 요청 | 사용자 행을 잠그고(`findByIdForUpdate`) 판정 행을 다시 읽어 `PENDING` 일 때만 진행한다 |
| 다음 단계 | ④ 결과 화면 |

### ⑤ 자정 자동 확정 — `PendingJudgmentFinalizer`

| | |
|---|---|
| 들어오는 조건 | 날짜가 지난(오늘 이전) 판정 행이 아직 `PENDING` — 그날 안에 사유 입력을 끝내지도, 건너뛰지도 않았다 |
| 언제 | 매일 00:00(한국 시간). 자정에 서버가 꺼져 있었던 경우에 대비해 서버가 뜰 때도 한 번 돈다 |
| 하는 일 | 예외 지출 사유를 반영하지 않고 **1차 판정 내용 그대로** 확정한다(D7). 다시 계산하지 않고 ①에서 저장한 신호·스탯별 결과·보상을 그대로 쓰고 그 보상을 한 번 지급한다. `FINALIZED`·`finalized_at` 기록 |
| 동시 요청 | ③과 같이 사용자 행을 잠근 뒤 다시 읽어 `PENDING` 일 때만 진행한다. 사용자가 자정 직전에 누른 확정과 겹쳐도 보상은 한 번 |
| 실패 | 한 건이 실패해도 나머지는 계속 처리하고 ERROR 로그를 남긴다. 그 건은 `PENDING` 으로 남아 다음 실행(다음 자정·서버 재시작) 때 다시 처리된다 |
| 다음 단계 | 끝. 그 날은 확정된 날로 보인다 |

### ④ 결과 화면

- 하루 신호와 보상(코인·스탯), 스탯 그룹별 판정 카드.
- 1차보다 **순해진** 그룹(빨강 → 노랑/초록)에만 「1차 판정은 빨강 · 과소비였지만 예외 지출 사유가 인정돼 초록 · 합리적으로 바꿨어요」를 붙인다. 더 나빠진 그룹(1차 뒤에 지출을 더 적은 경우)에는 붙이지 않는다.
- 가계부 달력·보상 칸: `FINALIZED` 만 판정 색과 받은 보상을 보여 준다. `PENDING` 이면 오늘은 「사유 답변 대기」, 지난 날은 ⑤가 처리하기 전 잠깐 「1차 판정으로 확정 중」.

## 3. 그룹 신호와 보상 계산 (①·③ 공통)

스탯 그룹마다:

1. **하루 봉투** — 월 예산을 날짜 수로 나눈 몫에, 전날 남긴 금액의 절반을 더하고 전날 초과한 금액은 전부 뺀다.
2. **신호** — 오늘 그 그룹 지출 합계가 봉투의 85% 이하면 초록, 봉투 이하면 노랑, 넘으면 빨강. 월 예산을 이미 다 써서 오늘 봉투가 0원이고 지출도 없으면 노랑(예산 소진).
3. **완화** — 신호가 빨강이고 그 그룹에 인정된 예외 지출이 있으면, 그 지출들의 최종 신호 중 가장 순한 것으로 바꾼다. 처음부터 빨강이 아니던 평범한 지출은 완화 근거가 아니다.
4. **보상** — 남긴 금액(봉투 − 지출, 0 이상) 1,000원마다 그 스탯 +1(그룹당 최대 15). 코인은 네 그룹 남긴 금액 합계의 1/100. 배치한 가구의 분양 보너스가 붙고 펫 스탯은 100 상한.

하루 신호는 네 그룹 중 가장 주의가 필요한 신호(빨강 > 노랑 > 초록)다.

> **완화는 신호만 바꾸고 보상은 바꾸지 않는다.** 예산을 넘긴 그룹은 남긴 금액이 0원이라 사유가 인정돼도 그 그룹 보상은 0이다.
> 인정된 금액만큼 보상도 늘리려면 Q1 (나)가 필요하다(5절).

## 4. 판정 밖에서 일어나는 일

| 상황 | 동작 |
|---|---|
| 지출 수정 — 내역 이름·결제수단만 바꿈 | 다시 판정하지 않는다. 지출 신호와 AI 질문·답변이 그대로 남는다(D6) |
| 지출 수정 — 금액이나 카테고리를 바꿈 | 그 지출을 다시 판정하고 AI 질문을 새로 만든다(빨강이면). 그날이 `FINALIZED` 면 하루 판정은 그대로다 |
| 확정 뒤 그날 지출 추가·삭제·답변 | 지출 쪽만 바뀌고 하루 판정·보상은 그대로다(D5) |
| `PENDING` 중 지출 추가·수정 | ③에서 다시 계산할 때 반영된다 |
| 자정이 지난 `PENDING` | 사용자는 확정할 수 없고 ⑤가 1차 판정 내용으로 확정해 그 보상을 준다. 그 뒤로는 확정된 날과 같다 |
| 월간 리포트 | `FINALIZED` 인 날만 센다 |

| D7 | **자정이 지나도록 확정하지 않으면** 예외 지출에 대한 판정 없이 **1차 판정 내용으로 보상**을 준다 (10-08) | 「자정이 지나면 예외 지출에 대한 판정 없이 1차 판정 내용으로만 보상을 주는 식으로 가야할 것 같아」 |
