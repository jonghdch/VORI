# 온보딩·인앱 튜토리얼 설계

> 신규 사용자가 첫날 VORI 의 핵심 가치인 "지출한 이유를 묻고 판정을 바꾸는 경험"까지 도달하게 하는 사용자 흐름.
> 구현 문서가 아니라 화면에 보이는 순서와 UX 원칙을 정리한다.
>
> 작성 기준: 2026-09-23. 참고 글: [웹 페이지 튜토리얼은 어떻게 만들까?](https://devlab.tistory.com/3)

## 설계 원칙

튜토리얼의 목표는 모든 기능 설명이 아니라 **첫 성공 경험**이다. 사용자가 처음 들어왔을 때 무엇을 해야 하는지 몰라 멈추지 않게 하고, 첫 지출 기록과 첫 판정 이해까지 짧게 데려간다.

원칙은 네 가지다.

| 원칙 | VORI 적용 |
|---|---|
| 3단계 이내 | 첫 방문 온보딩은 3장 이하로 끝낸다 |
| 건너뛰기 가능 | 모든 안내에 `건너뛰기`를 둔다 |
| 결과 중심 | "버튼 설명"보다 "무엇을 얻는지"를 말한다 |
| 반복 강요 금지 | 완료/스킵 상태를 저장하고 같은 튜토리얼을 반복 노출하지 않는다 |

VORI 에는 두 종류의 튜토리얼이 필요하다.

1. **첫 방문 온보딩 튜토리얼**: 가입 직후 한 번만 보이는 짧은 소개와 기준선 설정.
2. **인앱 튜토리얼**: 실제 화면 위에서 사용자가 첫 행동을 하도록 돕는 하이라이트 안내.

체크리스트형 튜토리얼은 보조로 둔다. 첫 방문 슬라이드와 인앱 하이라이트를 놓친 사용자가 홈에서 다시 따라올 수 있게 하는 장치다.

## 현재 문제

`users.tutorial_done` 컬럼과 `MeResponse.tutorialDone` 응답은 이미 있지만, 이 값을 `true`로 만드는 화면 흐름이 없다. 그래서 신규 사용자는 가입 직후 바로 홈에 들어오고, 무엇부터 해야 하는지 스스로 찾아야 한다.

더 큰 문제는 판정 기준이다. 현재 `ExpenseService`는 표본이 적을 때 z-score 계산을 건너뛰므로, 신규 사용자는 첫 5건 동안 VORI 의 핵심 가치인 개인화 판정을 제대로 경험하지 못한다.

따라서 온보딩은 단순 설명 화면이 아니라, **첫 지출부터 기준선을 어느 정도 갖게 만드는 흐름**이어야 한다.

## 전체 사용자 흐름

```text
회원가입 완료
  → 첫 방문 온보딩 3장
  → 소비 기준선 설정 3문항
  → 시작 펫 확인
  → 홈 진입
  → 인앱 튜토리얼 체크리스트 표시
  → 첫 지출 기록 안내
  → 가계부 작성 화면 하이라이트
  → 저장 후 결과 해석 안내
  → 첫 업적/칭호 안내
  → 튜토리얼 완료
```

## 1. 첫 방문 온보딩 튜토리얼

### 진입 조건

- 회원가입 직후 `tutorialDone == false`
- 또는 로그인 후 `tutorialDone == false`인 사용자
- 사용자가 이전에 `나중에 하기`를 눌렀으면 홈 체크리스트로만 재진입시킨다

### 화면 1 — VORI 는 무엇을 하는가

사용자에게 보이는 내용:

```text
VORI 는 지출한 이유를 묻는 가계부예요.

금액만 보고 판단하지 않고,
평소 소비와 오늘의 이유를 함께 봐요.
```

버튼:
- `다음`
- `건너뛰기`

의도:
- 가계부 + AI 판정이라는 핵심 가치를 첫 문장에서 알린다.
- 펫/게임 요소를 먼저 말하지 않는다.

### 화면 2 — 왜 기준선이 필요한가

사용자에게 보이는 내용:

```text
사람마다 평소 소비는 달라요.

VORI 는 남들의 평균이 아니라
내 평소 소비를 기준으로 빨간불·초록불을 정해요.
```

버튼:
- `다음`
- `건너뛰기`

의도:
- z-score/EMA 같은 기술어를 쓰지 않고 개인 기준 판정을 설명한다.

### 화면 3 — 기록하면 무엇이 생기는가

사용자에게 보이는 내용:

```text
합리적인 소비는 보리의 성장으로 이어져요.

아낀 금액은 코인과 스탯이 되고,
칭호와 마이룸도 하나씩 열려요.
```

버튼:
- `내 기준 설정하기`
- `바로 시작하기`

의도:
- 첫 행동을 "기준 설정"으로 유도한다.
- 스킵해도 서비스 이용은 가능해야 한다.

## 2. 소비 기준선 설정

### 목적

첫 지출부터 판정 경험을 주기 위해 최소한의 초기값을 받는다. 회의록의 긴 튜토리얼처럼 자산, 성별, 한 달 내역 전체를 요구하지 않는다.

### 문항 수

3문항으로 제한한다.

### 문항 1 — 평소 한 끼 식비

```text
평소 한 끼에 얼마 정도 쓰나요?
```

선택지:
- `8,000원 이하`
- `8,000~12,000원`
- `12,000~18,000원`
- `18,000원 이상`

영향:
- `ENERGY` 기준선 초기화 후보

### 문항 2 — 자주 쓰는 소비 영역

```text
요즘 가장 자주 쓰는 곳은 어디인가요?
```

선택지:
- `식비`
- `쇼핑·뷰티`
- `문화·여가`
- `생활·고정비`

영향:
- 사용자가 첫 지출을 어디에 기록할 가능성이 높은지 파악
- 인앱 튜토리얼에서 예시 카테고리 추천

### 문항 3 — 이번 달 목표

```text
이번 달에 가장 바라는 건 무엇인가요?
```

선택지:
- `충동구매 줄이기`
- `식비 아끼기`
- `기록 습관 만들기`
- `보리 키우기`

영향:
- 홈 체크리스트 문구 개인화
- 목표 API와 연결할 경우 기본 목표 생성 후보

### 완료 화면

```text
좋아요. 이제 첫 기록을 남겨볼까요?

첫 기록을 남기면 보리가 오늘 소비를 같이 살펴봐요.
```

버튼:
- `첫 지출 기록하기` → `/wallet/new`
- `홈으로 가기` → `/home`

## 3. 시작 펫 확인

신규 가입자는 이미 시작 펫을 받는다. 온보딩 마지막에 이를 명확히 보여준다.

사용자에게 보이는 내용:

```text
보리가 기다리고 있어요.

기록을 남길수록 보리의 스탯이 자라고,
성체가 되면 분양해서 새 알을 만날 수 있어요.
```

버튼:
- `첫 지출 기록하기`
- `마이룸 먼저 보기`

주의:
- 펫 성장 설명은 짧게 한다.
- 첫 목표는 게임 이해가 아니라 지출 기록이다.

## 4. 홈 체크리스트형 튜토리얼

온보딩을 완료했거나 건너뛴 사용자는 홈에서 작은 체크리스트를 본다. 강제 모달이 아니라 홈 카드 안에 노출한다.

### 노출 조건

- `tutorialDone == false`
- 또는 아래 체크리스트 중 완료하지 않은 항목이 있음

### 체크리스트

```text
VORI 시작하기

□ 첫 지출 기록하기
□ AI 판정 확인하기
□ 칭호 하나 확인하기
□ 마이룸에서 보리 보기
```

각 항목의 이동:

| 항목 | 클릭 시 |
|---|---|
| 첫 지출 기록하기 | `/wallet/new` |
| AI 판정 확인하기 | `/wallet` 의 AI 소비 판정 카드 |
| 칭호 하나 확인하기 | `/titles` |
| 마이룸에서 보리 보기 | `/raise` |

완료 기준:

| 항목 | 완료 판정 |
|---|---|
| 첫 지출 기록하기 | expense count >= 1 |
| AI 판정 확인하기 | AI 질문 답변 완료 또는 판정 카드 방문 |
| 칭호 하나 확인하기 | `/titles` 최초 방문 |
| 마이룸에서 보리 보기 | `/raise` 최초 방문 |

모든 항목이 끝나면:

```text
기본 사용법을 익혔어요.
이제 기록을 쌓으며 보리를 키워보세요.
```

이 시점에 `tutorial_done = true`로 저장한다.

## 5. 인앱 튜토리얼 — 첫 지출 기록

실제 화면 위에 하이라이트를 띄워 행동을 유도한다. 단계는 3단계 이내로 유지한다.

### 진입 조건

- 사용자가 `/wallet/new`에 처음 들어옴
- 아직 지출 기록이 없음
- 사용자가 이 튜토리얼을 스킵하지 않음

### Step 1 — 내역 입력

하이라이트 대상:
- 지출 내역 입력 필드

문구:

```text
오늘 쓴 것을 적어보세요.
예: 점심, 커피, 결혼식 축의금
```

목적:
- 무엇을 입력해야 하는지 막막함 제거

### Step 2 — 금액 입력

하이라이트 대상:
- 금액 입력 필드

문구:

```text
금액을 입력하면 평소 소비와 비교할 준비가 돼요.
```

목적:
- 금액 입력이 판정의 핵심 재료임을 설명

### Step 3 — 다음 단계

하이라이트 대상:
- `다음 단계` 버튼

문구:

```text
저장하면 보리가 오늘 소비를 살펴봐요.
```

목적:
- 버튼 기능보다 결과를 설명

## 6. 인앱 튜토리얼 — 판정 결과 해석

첫 지출 저장 후 결과 화면 또는 가계부 목록에서 보여준다.

### Step 1 — 신호등 배지

하이라이트 대상:
- 지출 행의 신호등 배지

문구:

```text
초록불은 평소보다 합리적인 소비,
빨간불은 이유를 더 살펴볼 소비예요.
```

### Step 2 — AI 질문 카드

하이라이트 대상:
- AI 소비 판정 카드

문구:

```text
빨간불이 뜨면 AI가 이유를 물어요.
답변에 따라 판정이 바뀔 수 있어요.
```

### Step 3 — 보상 안내

하이라이트 대상:
- 홈의 펫 카드 또는 상점의 코인 배지

문구:

```text
인정받은 소비와 절약은
보리의 스탯과 코인으로 이어져요.
```

## 7. 인앱 튜토리얼 — 칭호와 마이룸

첫 업적 획득 후 한 번만 보여준다.

### 칭호 안내

하이라이트 대상:
- 홈의 최근 업적 또는 `/titles` 상단 요약

문구:

```text
업적을 달성하면 칭호가 열려요.
획득한 칭호는 홈에 장착할 수 있어요.
```

### 상점 잠금 해제 안내

하이라이트 대상:
- 상점의 잠긴 가구 카드

문구:

```text
일부 가구는 칭호를 얻으면 열려요.
잠긴 상품도 조건을 보여줘서 다음 목표가 돼요.
```

### 마이룸 안내

하이라이트 대상:
- 마이룸 방 영역

문구:

```text
가구는 사기만 하면 끝이 아니에요.
방에 배치해야 분양 보너스가 적용돼요.
```

## 8. 상태 저장

서버 저장과 브라우저 저장을 나눠 쓴다.

| 상태 | 저장 위치 | 이유 |
|---|---|---|
| 온보딩 완료 여부 | `users.tutorial_done` | 계정 단위로 유지되어야 함 |
| 홈 체크리스트 완료 | 서버 권장 | 기기 바꿔도 이어져야 함 |
| 특정 하이라이트 스킵 | localStorage 가능 | UX 상태라 서버 필수 아님 |
| 기준선 문항 답변 | 서버 | `user_stat_stats` 초기화와 연결됨 |

서버에 최소로 필요한 API 후보:

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/tutorial/status` | 온보딩/체크리스트/인앱 안내 상태 |
| POST | `/api/tutorial/baseline` | 기준선 3문항 저장 및 `user_stat_stats` 초기화 |
| PATCH | `/api/tutorial/checklist/{key}` | 체크리스트 항목 완료 |
| POST | `/api/tutorial/complete` | `tutorial_done = true` |
| PATCH | `/api/tutorial/skip` | 온보딩 스킵. 체크리스트는 남김 |

## 9. 구현 라이브러리 선택

현재 VORI 는 React 앱이므로 인앱 하이라이트는 다음 중 하나가 적합하다.

| 선택지 | 판단 |
|---|---|
| `react-joyride` | 단계·진행률·스킵·조건부 실행이 필요하면 적합 |
| `driver.js` | 가볍고 한 줄 설명 중심. VORI 의 짧은 하이라이트에 적합 |
| 직접 구현 | 첫 방문 슬라이드와 홈 체크리스트는 직접 구현 가능 |

추천:

```text
첫 방문 온보딩: 직접 구현
홈 체크리스트: 직접 구현
인앱 하이라이트: driver.js 또는 react-joyride
```

VORI 의 인앱 튜토리얼은 단계가 길지 않으므로 `driver.js`가 더 가볍다. 다만 여러 페이지를 넘나드는 투어와 완료 상태 관리를 라이브러리 안에서 많이 처리하고 싶다면 `react-joyride`가 낫다.

## 10. 하지 말 것

- 가입 직후 긴 설문을 강제하지 않는다.
- 모든 메뉴를 한 번에 설명하지 않는다.
- 펫·가구·칭호를 먼저 설명해서 가계부 핵심을 흐리지 않는다.
- 스킵한 사용자를 매번 모달로 다시 막지 않는다.
- "이 버튼은 무엇입니다" 식의 기능 설명만 하지 않는다.
- 첫 지출 전부터 예산·목표·리포트까지 모두 설명하지 않는다.

## 11. 최종발표 전 최소 구현 범위

최소 범위는 다음이다.

1. 가입 직후 3장 온보딩
2. 기준선 3문항
3. `/wallet/new` 첫 방문 하이라이트 3단계
4. 홈 체크리스트 카드
5. `tutorial_done` 저장

이 정도면 "신규 사용자는 첫 5건 동안 핵심 가치를 못 본다"는 현재 약점을 설명이 아니라 제품 흐름으로 보완할 수 있다.
